# 把自己的 Python 工程结果带回手账

五份现有工程都可以使用同一个本地自测工具。它运行你本机的公开测试，记录逐项结果，并把这次运行与源码、测试和固定样例的 SHA-256 关联。游戏读取报告后，会指出缺材料、改稿、失败、跳过、超时或进程异常；你可以修改后再带回新的作品记录。

本机自测与可信审核分别显示。报告是可编辑的自报材料，公开测试通过不代表独立构建、排错、迁移或长期掌握已经核验；课程成绩、奖励和审核签名规则保持原样。

## 1. 输入是什么，要交出什么

继续使用已经领取的学生工程。原学生包、任务 ID、合同和各章正文都没有被替换。

| 工程／`--task` | 要处理的真实输入 | 要做出的输出 | 这次公开自测的口径与工程交付要求 |
|---|---|---|---|
| 仓库交班 `stockledger` | 两份 `item,qty` CSV，严格处理引号、重复商品、零数量和非法行；可选 `--reserve N` | 全部满足才扣库存的 JSON 报告；可从其他目录启动的 CLI／pyz | 实现 `core.py`、`files.py`、`cli.py`；检查重复累加、坏输入不覆盖旧报告和安全库存边界。再写至少三个有理由的新测试，并交付 Build／Debug／Transfer 说明。 |
| 可靠修补 `repo-repair` | 包内临时 Git 仓库、问题、读取／补丁／验证决策和精确授权 | 实际文件差异、验证结果、事件记录和可重启的检查点；迁移至借用提醒 | 实现 `repair.py`、`host.py`、`transfer/reminders.py`；读取范围、补丁摘要、授权、修后验证和失效恢复都要符合合同。公开用例不代替自己的新问题分析。 |
| 可靠派送 `durable-dispatch` | 虚构请求、SQLite 状态、响应丢失、重试与授权、容量与航次变化 | 可跨进程恢复的待发箱、接收回执、旧工人拒绝、个人工作流及两种迁移结果 | 实现九章业务模块；检查事务、幂等、租期、批准和恢复。保留真实两侧 SQLite 观察、失败反例和迁移说明。 |
| 工具桥 `tool-bridge` | 虚构商品／时段、CLI 与本地 HTTP／stdio 请求、固定评测样例 | 同一业务合同的三个入口、错误与资源回收、事件轨迹和独立评分记录 | 实现 `toolbridge/`；逐项检查业务、传输、MCP 子集、事件、评测、迁移及资源回收。另按原手册运行 `run_experiment.py`、整理真实实验结果。 |
| 可复查研究 `evidence-research` | 虚构港口与维修活动语料、会话范围、提问、来源版本和撤回 | 有引文与条件的回答、更新后的撤回／重查、持久记忆和评价 | 实现 `research_lab/`；检查检索、来源支持、范围、预算、更新与迁移。公开样例只覆盖明确的窄合同；另交自己的语料实验、反例和报告。 |

自测工具不替你填写 `DELIVERY.md`，也不生成上述工程作品。原五份工程的阅读链接、章节任务和独立交付要求仍是完成依据。

## 2. 在 VS Code 的终端运行

解压 `local-check-tools.zip`，将工具目录放在学生工程目录旁边。工具仅含 Python 标准库代码、固定检查配置与这份说明，不需要安装包。请使用自己的学习工程；它会在本机执行该工程的测试和代码，并不是未知代码沙箱。

在 VS Code 打开学生工程，终端当前目录应含 `tests/` 和项目源码。先确认解释器：

```text
python --version
python -B "../local-check-tools/local-check.py" --task stockledger --project .
```

另外四份只替换任务名称：

```text
python -B "../local-check-tools/local-check.py" --task repo-repair --project .
python -B "../local-check-tools/local-check.py" --task durable-dispatch --project .
python -B "../local-check-tools/local-check.py" --task tool-bridge --project .
python -B "../local-check-tools/local-check.py" --task evidence-research --project .
```

Windows 若使用 Python Launcher，可把命令开头的 `python` 换成 `py -3`；路径有空格时保留引号。以上 Windows 命令是操作说明，本轮没有 Windows／VS Code 真机验收。

推荐 Python 3.12。源码和样例保存为 UTF-8 **无 BOM**；工具发现 BOM 会列出文件并拒绝生成新报告，可在 VS Code 的编码菜单另存为 UTF-8 后重跑，工具不会替你修改源码。各工程原有最低解释器要求保持：工具桥和可靠派送至少 3.11，可复查研究至少 3.10。默认整个检查最多 60 秒；确有设备需要时可在同一命令后加 `--timeout-seconds 120`，范围 1—300 秒。增加时限不能解决死锁。

工具使用 `unittest` 的发现与运行接口，执行 `tests/test_*.py`；可靠派送显式使用项目根作为顶层目录。工具桥同时将项目与测试目录加入子进程的 Python 模块路径，与它原来的公开检查入口一致。报告中的 `command` 是固定的 unittest 检查方式，不是从上传材料取出的可执行命令。

## 3. 读终端和报告

工具在工程根目录生成 `LOCAL-CHECK.json`。它记录任务、合同、解释器、退出状态、时限、逐项测试结果、输入文件摘要，以及运行前后是否改稿。只要形成报告，失败和超时也可以带回；初始未解学生包出现未实现错误是正常起点。

| 终端退出码 | 含义 | 下一步 |
|---|---|---|
| 0 | 所发现用例全部通过、无跳过、进程正常、检查期间输入未变 | 带回报告和对应材料，仍接受独立审核。 |
| 2 | 有失败、错误、跳过、空测试、未完整结果或检查期间改稿 | 读逐项结果，修复后重跑；保留旧失败作为排错说明。 |
| 3 | 超时，已尝试结束本次检查进程树 | 检查循环、任务等待、服务与子进程回收，再重跑。 |
| 4 | 路径、UTF-8、大小或工具准备有误，未能完成新报告 | 按终端提示修正；旧报告不能冒充本次新运行。 |

测试结果不会由 `passed: true` 决定。没有用例、只跳过用例、报告含额外字段、重复路径、错误任务／合同、非零退出码或异常结束，都不会显示“本机自测通过”。仅改变报告日期也不能让旧报告对应新源码。

## 4. 在游戏里核对并保存

打开代码工坊的独立工程区域，选择对应委托并领取；选择你的专用作业目录，排除无关文件后预览。把 `LOCAL-CHECK.json`、报告列出的源码／测试／固定样例以及必需交付说明一起收录。

预览下方有“本地自测报告与材料一致性”。缺少报告对应文件会逐个列出；改了某段代码、增添测试或检查期间改稿，会明确要求重跑。报告与材料一致时仍会区分“通过”“有待修项”“跳过”“超时”“进程异常”，可展开看逐项结果。

确认清单后保存为待核验作品。成功保存的报告随这一版提交包保存；关闭并重新打开旅程后，游戏从那一版已保存的字节重新核对。后续改稿和报告应另存一次作品，不会覆盖旧作品。未确认保存时仍应保留本机目录或下载提交包。

最小提交仍限制为 48 个文件、每个 64 KiB、总共 512 KiB；报告占一个文件。工具只绑定公开检查对应的注册源码、测试与固定输入，不把 `work/`、`evidence/` 生成报告、根目录 `RESULT.json`／`CHECKPOINT.json`／`MANIFEST.json` 当成测试输入。那些工程实验材料仍可按原任务规则另外提交，不能据此声称已经运行。优先保留必须的源码与测试，在预览中排除重复教学文档。

## 5. 结果的边界

游戏只读取文本和计算摘要，不执行上传的 Python，不联系审核服务。自测报告和测试本身都可以被本人编辑，工具运行的是当前目录实际存在的测试；它不能证明测试足以覆盖原合同，不能取代可信执行、签名审核或独立学习观察。原可信审核表仍为空，作品保持“待核验”；独立构建、排错、迁移仍显示各自尚未评估的状态。当前报告也不证明原 AE26 全部 38 个实验、Windows 环境恢复、操作系统隔离或结业答辩已经完成。
