# 第二站：允许看什么，要在排名前确定

目标：建立可重建索引，解释每一个关键词分数，拒绝过时索引，并让公开低分资料不会被私有高分资料挤掉。

## 先让错误顺序失败

另造三段花园资料：私有段含 `garden gate code`，公开段只含 `garden gate`，无关段含 `river weather`。问题 `garden gate code`，预算一段。先把所有段评分、取第一段、再删私有段，结果为空；公开证据仍存在，却没有机会进入结果。修复是先使用宿主 `allowed_access` 形成候选，再评分和 top-k。

访问标签来自本地实验的宿主配置；正文写“我公开了”不算授权。查看 `data/alice.json`，它只是练习配置，不能充当多用户服务的认证。你不需要在本任务编造登录系统。

## 再逐步增加匹配规则

对 `Garden, gate GARDEN` 先调用 casefold，再 split。去掉单词两端合同列出的标点，滤掉空词；不要删掉单词中间的字符。查询中的重复 garden 只计一次，可以用 set，也可以用已见词列表。文本重复词可以保留，分数仍由不同查询词决定。

先实现 `tokens` 和 `keyword_score`，用自己的大小写、标点、重复词、零命中四题检查，再写 `build_index`。索引保留每片段的文档 id、原段序号、原位置、向量及访问/日期元数据。保留整段，不擅自切掉尾部的否定或例外。

实现 `search(...,mode='keyword')` 的顺序：核索引、过滤权限与生效日期、计分、去零分、排序、按文档去重、截预算。排序键使用分数的负数和 id，保证高分在前、同分稳定。一个文档有十个命中段不应占满十个返回名额。

## 索引不能永久相信自己

先生成索引，再修改原文；若照旧索引回答，你会看见仍返回旧词。三种变化都需要重建：文件 bytes 改了、添加文件、删除文件。访问撤回和替代关系变化也在完整 bytes 摘要里。

这个小规模适配器为最多 64 个文件做完整一致性检查，优先易复核，不宣称高性能在线索引。不要为了少读文件就去掉版本核对；真实大规模系统需要另外设计可信更新事件、访问撤回与并发快照。

## 练习与反馈

执行 `python -m unittest discover -s tests -v`，先关注 RetrievalContract 的关键词、索引和权限检查。若“公开资料明明存在但结果空”，先打印**授权后的候选 id**；若“改原文后仍旧答案”，检查当前文件摘要和 snapshot；若无关第一条被返回，检查是否给零分加了兜底。

独立应用：把私有段放到不同输入位置，改 limit 为 1、2，证明结果不依赖文件先后。再写一个同义表达题，让关键词确实漏检，并明确记录这次属于匹配机制的能力边界，进入下一站。
