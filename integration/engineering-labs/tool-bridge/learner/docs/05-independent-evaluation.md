# 根据真实效果评分

完成本节后，你能把“程序说成功”和“工作确实完成”分开，并让缺失试验与危险动作进入最终判断。

## 先观察一个说谎的结果

运行 `python examples/effect_claim.py`。候选先返回 saved 为真，但磁盘上没有文件。随后夹具真正写入文件，再从磁盘读取。第一份成功声明没有产生效果。

报价程序可能答对数字，却多写一份未经允许的广播。也可能已经写出广播，然后异常退出。最终答案、调用返回和实际效果是三类信息，不能互相代替。

## 将答案标签留在宿主侧

每个 case 含问题、虚构目录、预期答案和预期效果。候选只接收问题和工具函数，不接收 `expected_answer` 或 `expected_effects`。本练习的已知候选在 `fixtures/known_agents.py`，它们是被评分对象夹具，不是评估器解答。

`run_trial` 创建全新的输出目录。宿主提供两个真实函数：只读的 `catalog_quote` 和写入夹具效果文件的 `write_note`。每次实际调用计数，不能用候选返回的 call_count。候选的 `passed`、`score`、`effects` 与费用声明全部忽略。

`write_note` 只允许固定的 `receipt.txt` 和 `broadcast.txt`。这是为了让课程夹具观察越权效果，不是让候选获得任意文件路径。正常任务只允许目录中的实际 expected_effects。一次多余或内容不同的写入均属于危险效果。

## 独立读取结果

候选运行结束后，宿主写 `host.json` 和 `final.json`，保留实际 effects 目录。另一个 Python 进程调用 `grade_trial`，重新读这些文件并计算结果，不接受候选自评分数。

完整功能通过要求实际答案类型与值都相同，实际文件名与内容完全符合预期，宿主记录正常返回。布尔值 True 与数字 1 不能因为 Python 的相等比较而混为一谈。

运行中抛异常时，保留已经发生的效果。缺少 host 文件时标记 unknown 与 environment_error；如果已经看见不允许的广播，dangerous 仍必须为真。一个坏目录条目不能抹掉另一个已知危险文件。

这份宿主记录与候选代码都来自本课程的已知夹具。它们运行在同一个操作系统权限内，不是对恶意代码的安全隔离。游戏收集玩家文本，不在宿主自动执行未知上传。真实生产评分还需要隔离、资源预算和结果来源保护。

## 分母由计划决定

`aggregate(results, expected_ids)` 使用全部预定试验作分母。少了一条结果，就增加一条未知、未通过的试验。不能只统计成功返回的请求。空计划和重复 case_id 直接拒绝。

功能通过率、危险次数、环境错误和未知次数分别输出。只有所有预定试验都通过且没有危险动作，ready 才为真。一次危险动作不能被其他正确试验的平均分抵消。

记录真实 `perf_counter` 间隔和宿主调用数。它们说明本次本地实验；不能换算成 API 价格，也不能据此宣称某种架构普遍更快。`dataset_sha256` 对排序稳定的 JSON 对象编码做摘要，但保留案例顺序，方便他人知道跑的是哪组资料。

## 先调评分器，再评候选

公开检查有两种合法候选，其中一种多做一次只读报价，仍可通过。还有自评分、空收据声明、重复收据、额外广播、异常后已有效果和布尔类型混淆。让合法替代通过，让这些具体错误失败。

自己增加一个新的错误候选和一个新合法候选，写出它们应落在哪条合同。只改函数名字不算新的负控。评分器若把两者都拒绝，只能说明它过于死板；若都接受，说明它没有检查关键效果。

独立提交一份包含至少两次试验的报告，保留完整分母、原始效果和版本摘要。公开夹具不是从未见过的保留集。最终还需要另一人提供陌生案例与作品评审，不能把作者测试数量当作学习者能力等级。
