# 从真实记录还原运行

完成本节后，你能记录真实调用，并在并发、重试、失败、取消和缺失记录时保留正确的判断边界。

## 身份先于时间排序

运行 `python examples/span_identity.py`。位置配对会把先结束的另一个操作误认成先开始操作的结果。按操作身份配对，才能得到正确的时长。

为一次运行分配 `run_id`，为其中每次尝试分配 `span_id`。第二次尝试获得新的 span；`operation_id` 可保持不变，表示它们是在重试同一件事。第二次启动可以再次使用局部 span 名称，所以配对键必须是 `(run_id, span_id)`。

`parent` 指向该 span 所属的操作。它不是“上一行日志”。两个分支可以交错，子操作仍属于原来的父操作。缺少父记录时保留孩子并报告 `missing_parent`，不要删掉孩子伪造一棵完整的树。

## 只记录允许的内容

`write_event` 把事件追加到 UTF-8 JSONL，一行一个 JSON 对象。使用追加模式，不覆盖前面的尝试。每次写完 flush，本练习还调用 `os.fsync` 请求刷新文件；这不使业务操作与日志成为一个原子事务，也不保证所有硬件故障下都能恢复。

只保留合同允许的字段。原始输入对象保持不变。正文、异常消息、密钥和任意工具结果不能顺手写进去。运行与操作标识由宿主从有限名称中产生，不从用户正文拼出。字符格式合法不代表内容不会泄漏。

每个进程写自己的日志文件。两个 worker 分别写 `left.jsonl` 和 `right.jsonl`，协调进程写 `root.jsonl`。读回时汇合。这份设计没有宣称多进程可安全地同时追加同一个文件。

如果最后一行没有完整换行，`read_events` 返回前面的完整行，并标记 `partial_tail`。它不能改写原文件或把尾部补成成功。完整的一行若是坏 JSON，则直接报告损坏。

写入函数也拒绝在不完整尾行后追加。先保留损坏文件，在新的运行文件中继续记录；不要把新事件接到半截 JSON 后面而破坏两条证据。

## 包住真实操作

`observe` 先记录开始，再真正 `await operation()`。返回后记录 ok，并返回原结果。普通异常记录 error；取消记录 cancelled。两者都继续向调用者传播，不转换成正常返回。

开始日志写失败时，本合同选择不执行操作。结束日志写失败时，操作可能已经产生效果。两种情况必须分别测试。

还有两个错误同时发生的情况。操作已经抛出 `OSError` 或 `CancelledError`，结束日志又写不进去。必须保留原异常对象的身份和取消语义，把日志错误附在 `trace_log_error` 属性，并用 `add_note` 只附错误类型。若操作本来成功，则结束日志失败本身仍要抛出。不能让诊断错误冒充业务成功，也不能用诊断错误打断任务取消。

## 时钟与进程的边界

使用 `time.perf_counter()` 比较同一进程内一段操作的起止间隔。事件保存毫秒，源时钟提供秒。传入受控时钟只能验证乘以 1000 的计算，不证明真实运行速度。

进程 PID 由写入函数从 `os.getpid()` 获取，不相信调用者自报的 PID。同一 span 的开始与结束必须来自同一进程。不同进程的 perf_counter 数值不能直接相减，所以跨进程的 parent 是逻辑归属，本练习不据此计算跨进程时间包含关系。

父、子与并行区间会重叠。不能把所有 span 的 elapsed_ms 相加，当作整个任务耗时。

## 运行一次交错与重试

公开夹具的 left 先开始读取并等待一个明确信号。right 真正尝试读取一个不存在的文件，失败后创建该文件，再执行第二次读取。第二次读取结束后才放行 left。

这不是手填的时间线，也没有用固定延时假装发生过失败。第三个进程重新读取真实 JSONL，即使输入文件顺序倒过来，也要正确关联。right.try-1 的 error 必须保留，right.try-2 的 ok 不能覆盖它。

## 缺失记录时保留“不知道”

删掉日志副本中的一条结束记录，再汇总。该 span 状态必须为 incomplete，耗时为 None。不能写 running，也不能用根节点成功补成子节点成功。下一步应查实际进程状态、接收方结果或持久状态。

遇到结束日志缺失不能立即重发一个可能已经完成的写操作。日志是证据之一，不是对实际世界的完整替代。可选 `cause_span` 只是宿主给出的故障关联；汇总器核对目标是否存在 error 结束事件，没有证据时报告 `unverified_cause`，不自动证明根因。

## 独立排错

给自己的另一个工具加 `observe`，展示成功、普通异常、取消、开始日志失败和结束日志失败。保留真实效果文件。再交付两份日志副本，一份缺结束事件，一份缺父记录，写出你能证明什么、不能证明什么以及下一项核查。

第一层提示是画出 run、span、parent 三个字段。第二层提示是先按键分组再配对，而不是按列表位置 zip。最后才检查详细的身份、重复事件、环和时间边界。
