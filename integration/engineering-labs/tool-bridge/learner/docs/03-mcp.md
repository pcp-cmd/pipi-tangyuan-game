# 两个真实进程之间的 MCP 工具调用

完成本节后，你能实现固定版本的 stdio 工具服务器与客户端，处理初始化、请求、通知、错误和进程退出。本工程固定 MCP `2025-11-25`，不是对最新规范或完整协议的实现承诺。

## 先运行一条可见的管道

运行 `python examples/line_parent.py`。父进程创建一个真正的子进程，把一个带 ID 的单词长度请求写到 stdin，再从 stdout 读取回答。

`write` 把字节放入缓冲区，`await drain()` 等待管道能够继续写。子进程 `flush=True` 让一行立即送出。只在 EOF 后 `communicate()` 一次性检查输出，会漏掉“服务一直等关闭才回答”的错误。本例在连接仍打开时读取响应。

这段单词例子不是 MCP。它只教换行、UTF-8、ID 与资源关闭。接下来才增加 JSON-RPC 与 MCP 的规则。

## 请求与通知不同

JSON-RPC 请求带 `jsonrpc: "2.0"`、`id`、`method`，可有 `params`。响应带同一个 ID，并且只能有 `result` 或 `error` 其中一个。ID 是关联身份，不是消息在列表中的位置。

通知没有 `id`，不获得响应。服务器可能在请求与响应之间写出日志通知。客户端不能把“下一行 JSON”直接当作当前答案。错误的 ID、布尔 ID、缺失 ID 或结果与错误同时出现，都要使连接失效。

stdout 只用于协议消息。stderr 可以写诊断，客户端必须持续读取并丢弃或受控保存它，否则管道填满可能让服务器卡住。stderr 有文字不等于业务失败。

## 初始化是一个状态转换

| 当前状态 | 输入 | 下一步 |
| --- | --- | --- |
| new | 合法 initialize 请求 | 返回版本、能力和 serverInfo，进入 initialized |
| new | 提前的 initialized 通知 | 保持 new，不回复 |
| initialized | initialized 通知 | 进入 ready，不回复 |
| new 或 initialized | tools/list 或 tools/call | 返回本练习的 -32000 错误 |
| ready | tools/list 或 tools/call | 按工具合同处理 |

客户端请求的版本与服务器支持的版本必须明确核对。能力里声明 `tools` 才能调用本练习的工具。`notifications/initialized` 在成功初始化之后发送。工具元数据和 `readOnlyHint` 只是描述，不能给工具额外的文件或网络权限。

本项目只公开 `catalog_quote`。目录路径由启动命令确定，调用者不能通过参数重选根目录或添加 `approved` 取得权限。

## 区分两类错误

未知方法属于协议错误。`tools/call` 的 arguments 不是对象，也属于外层调用结构错误。已找到工具且 arguments 是对象后，如果数量类型错误或 SKU 不存在，就返回工具结果的 `isError: true`。

客户端必须先看外层 `error`，再看工具层 `isError`，最后才解析文本里的报价 JSON。如果同时提供 structuredContent，两个表示必须一致。

固定工具的 schema 在 [合同](CONTRACT.md) 中列出。你要实现这些字段的语义检查；不必制造一个假的“通用 JSON Schema 引擎”。基础实现没有资源、提示词、采样或并行多请求能力。

## 真实等待、取消和关闭

`asyncio.create_subprocess_exec` 接收参数列表，禁止用拼接的 shell 字符串。一个连接只允许一个待回复请求。用 `asyncio.timeout` 包住整个等待，日志通知不能重新开始总时限。

超时或取消后，尽力发送取消通知，然后关闭 stdin，等待进程退出；仍未退出才 terminate，最后在必要时 kill 并再次 wait。连接从此失效。`close` 重复调用仍须安全。

取消通知不代表服务端已撤销操作。超时只证明客户端没及时取得结果。未来把报价换成发信或扣款时，必须另外设计授权、幂等和对账，不可照搬自动重发。

## 练习与分层提示

先完成初始化与列工具，保持管道打开。再完成合法报价。之后依次测试参数错、未知商品、通知交错、错误 ID、EOF、超时和取消。每种故障后检查子进程已经退出。

如果提前通知就能调用工具，检查状态是不是只有一个 `ready` 布尔值。若一次错误后下一请求错位，检查是否继续复用了已经失效的连接。若通知不断到来使测试不结束，检查总时限是否被每条消息重置。

独立加一个你自己写的协议 peer，让它在回答前发两条通知，再返回正确 ID。另写一个 result 与 error 同时出现的错误响应。说明两者为什么不能都返回成功。

作者的额外互操作检查使用实际安装的 Python MCP SDK 1.29.0，覆盖双向初始化、工具发现、调用、错误和关闭。该 SDK 对未知方法返回 -32602 的实际差异另有记录；本项目服务器的未知方法合同仍为 -32601。双向工具互通不等于完整规范认证，也不要求学生安装依赖才能开始学习。
