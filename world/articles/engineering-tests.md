# 好测试要能让一种具体错法露出来

折扣程序在价格100、折扣20时输出80，看上去没有问题。但恒返回80的程序也会通过这一个样例。测试的任务不是再算一遍漂亮结果，而是找出一个输入，让正确规则和某种错误规则走向不同结果。

本课写的是 `check_discount(candidate)`。candidate由调用者提供，你的测试必须实际调用它。正确规则是价格乘以折后比例，价格非负、折扣百分数在0到100之间。测试接受正确实现，遇到指定错法要抛AssertionError，不能只打印“错了”然后正常结束。

## 先在更小的函数上看断言

下面的普通Python例子测试“数值加二”，不是折扣题答案。例子里的 `lambda 参数: 表达式` 会创建一个小函数，表达式的结果就是返回值。例如 `lambda value: value + 2` 相当于一个接收value并返回value加2的函数，可直接交给测试器调用。

```python
def check_add_two(candidate):
    actual = candidate(5)
    assert actual == 7, ("输入5", actual)

check_add_two(lambda value: value + 2)
try:
    check_add_two(lambda value: 7)
    check_add_two(lambda value: value + 1)
except AssertionError:
    print("检测到少加一次")
```

输出 `检测到少加一次`。其中恒返回7通过了第一个测试，说明单点断言的分辨力有限；最后的加一错法被拦下。`assert` 条件为真继续，为假抛AssertionError。消息里的实际结果能帮助定位，但通过与否来自比较，不来自消息文字。

测试自己也有输入合同。为了找错而向折扣函数传字符串或负价格，不是在检验本课要求的实现，反而可能误拒绝一份合法程序。先在题目允许的范围中寻找能分开的输入。

## 四种错法需要怎样的差异

恒返回80需要另一个正确答案不为80的案例；把百分数当金额直接相减，需要价格不同于100来拉开差距；整除会截去小数，需要一个正确结果确有小数的案例；漏掉100%需要触及完整优惠的端点。这里给的是选输入的理由，你仍要自己确定输入、独立计算期望并写出调用断言。

再加一份正确写法核对测试本身。`price*(1-percent/100)` 和 `price*(100-percent)/100` 都表达同一业务，某些浮点输入可能有微小舍入差别。选择可清楚核对的例子，或使用合理小容差；不能把严格依赖某条算式的浮点末位当成错误证据。容差也不能大到放过被截掉的小数。

不要写 `assert 自己算出的答案 == 期望` 而不调用candidate，这只检查测试作者会算术。也不要对所有异常一律当通过：正确实现不应抛错，错误实现需要由你的测试形成AssertionError失败。测试代码同样可能有错，先对已知正确和已知错误的小替身分别运行。

## 测一个分段收费规则

独立设计停车计费测试：前两小时免费，之后每开始一小时收费3元，上限12元，输入是非负的小时数。先写出规则对应的正确小函数，再造“整小时才收费”“忘了上限”“免费边界少一小时”三种错法。写一个只接收candidate的测试函数区分它们。

自核时逐例说明它针对哪种错法，检查2小时、刚过2小时、上限附近和很长时长，并验证正确实现被接受。新题多了分段、向上取整和封顶，不能仅替换折扣公式。它属于手工审查的独立练习，不自动增加本课成绩。
