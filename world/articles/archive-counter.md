# 到了同一种货，不等于这批货到齐了

清单里有四条绳，到货只见一条。集合能说明“绳出现了”，却说不出还缺三条。你要保留每次出现的次数，才能把预期数量与实际数量对上。

本课两份输入都是字符串列表。每一项代表一件货，同名可重复。结果是“名称到缺少数量”的普通字典，只保留正缺口；多到与额外物品都不列入缺货报告。

## 从出现记录变成计数

`collections.Counter` 是按值累计次数的容器。下面在普通Python中只观察点名册，尚未计算两份货物清单的差。

```python
from collections import Counter

visits = Counter(["east", "west", "east", "east"])
print(visits["east"], visits["west"], visits["north"])
visits.subtract(["east", "north"])
print(visits["east"], visits["north"])
```

输出 `3 1 0`，然后是 `2 -1`。构造时每出现一次就加一，读一个未记录的键得到零。`subtract` 会在容器里保留零或负计数，所以“用了Counter”本身并不保证结果只有正数。

对当前任务，把预期和到货分别计数，再逐种理解差额。预期4件、到1件，缺3；预期1件、到2件，差为负，但缺货报告里不应出现负数。Counter的二元减法与subtract方法对非正结果的处理不同；无论选哪种写法，都要确认最后交回普通字典且只含正项。

## 重复记录是这题的信息

预期 `['鱼','鱼','水']`、到货 `['鱼']` 应缺鱼1、水1。若先把两份输入转集合，鱼那一件剩余缺口消失。若只检查 `name not in arrived`，会得到同样错误，因为“有没有一件”和“够不够全部”不是同一个条件。

没有到货时，返回预期每种货的完整数量。没有预期时，即使多到许多灯也没有缺口。刚好到齐得到空字典，不留下数量0的键。这与收据汇总课必须保留零键的要求不同：前者是缺口报告，后者是发生过的账目。

排错先写一张三列小表：名称、预期次数、到货次数，再核对差值是否只筛选了正项。数量与名称是否排序是两回事；当前字典结果没有额外的按名称排序要求。

## 把重复事件当作重送，而不是多一件货

另做扫描收货报告。每条扫描记录有包裹ID和货物名，同一包裹ID重复扫描只计一次；不同ID但同名仍分别计数。再与预期名称列表比较缺口。

让一件鱼连续扫描三次，另一件鱼有独立ID，并加入同ID却换货物名的冲突记录，先确定冲突应报错的规则。检查先按ID去重，再按名称计数，避免把重送当作数量。输入从简单出现列表变成带身份的事件，原计数函数需要新的前置处理。此迁移题作人工核对，不自动登记通过。
