# 只带买得起的东西

汤圆想先看看“单件价格不超过预算”的所有商品。这不是把钱花出去的购物过程。遇到一件可以买的商品后，不应该从预算扣钱再筛下一件；每一件都与同一个上限比较。

本课入口 `affordable(prices, budget)` 返回合格价格的列表，保持原顺序和重复项。你已会for取当前项、if判断、append追加，也会从函数返回一个结果。现在把这些步骤分工组合。

## 判断一项，决定要不要放进新名单

先用普通Python把站名变成长度记录，只演示“输入一项，产生一项，再保留顺序”。

```python
names = ["港口", "灯塔顶", "港口"]
lengths = []
for name in names:
    lengths.append(len(name))
print(lengths)
print(names)
```

输出 `[2, 3, 2]`，原名字列表仍为 `['港口', '灯塔顶', '港口']`。重复名字没有被去掉。新结果从空列表开始，每次append都发生在当前已有结果之后。

筛选多了一道门。取到价格后，先决定它是否符合上限；符合时才进入结果，否则继续下一项。结果长度可以小于输入长度。不要在遍历的原列表上删除不合格项，删除会改变之后的位置，容易跳过下一件。

## 不是排序，也不是凑一篮总价

对于价格 `[12, 8, 12, 20]`、上限15，应保留前面三项的原排列。排序会变成8先出现，集合会把两个12合并，两者都改变了合同。

价格等于上限时仍入选。0与负数也按数值大小比较，本课检查会使用它们。现实商品是否允许负价是另一条业务规则，不能因故事叫“价格”就偷偷过滤负数。

空输入应交回空列表，所有项不合格时也是空列表。若在循环内部第一次命中后就return，后面合格项都没机会被看见。先确定何时结束整次筛选，再安排return的位置。

## 这次真的只带一篮货

另设计一个顺序购入程序，接收一列非负整数价格与初始预算。从左到右考虑，买得起就买并扣款，买不起就跳过继续。返回买入的原索引列表和剩余预算，不改变价格列表。

用 `[7, 5, 3]`、预算10手算，解释为何同一列数据在“单件筛选”和“逐件扣款”中可能得到不同结果。重复价格也要用原索引分开。

自核等额买入、跳过一件后仍能买后面、零价和空输入，并检查“支出加余额等于初始预算”。这是新增跨项状态的自核练习，不是把原筛选输出直接当购物凭据。
