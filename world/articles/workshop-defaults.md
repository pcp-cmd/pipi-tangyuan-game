# 不会串单的便签

皮皮给第一张订单加了“少盐”，下一张订单还没写备注，却已经带着“少盐”。问题不在打印机，而在两次调用共用了同一份默认列表。

本课实现 `append_note(note, notes=None)`。未提供notes或明确传None时，从空列表开始；提供列表时，保留原列表不变。每次都返回一个加入note的新列表，重复便签与空字符串也照常追加。

## 默认值什么时候创建

函数定义执行时，Python就计算默认参数的值。后面省略这个参数的调用，会得到同一个默认对象。如果默认值是会被修改的列表，多次调用就可能共享内容。

用下面的故意错误小例观察共享。它不是本课答案。

```python
def collect_bad(label, bucket=[]):
    bucket.append(label)
    return bucket

first = collect_bad("红")
second = collect_bad("蓝")
print(first)
print(first is second)
```

输出是 `['红', '蓝']` 与True。即使first在第二次调用之前已经返回，它指向的列表仍被第二次调用改了。每次return并不等于自动生成一份快照。

本课用None作为“没有提供列表”的标记。None不是空列表，检查它之后仍要决定在哪里创建列表。不要把默认值换成None后，却又把同一全局列表交给所有调用，那只是把共享位置挪了一下。

## 调用者提供列表也不能原地追加

题目要求每次结果都是新列表，包含原先内容以及新便签。如果直接对notes调用append，调用者的原件也会改变。你需要为本次结果建立新的外层列表，再在那份新列表上追加。

空列表同样是调用者明确传来的对象，不能因为它现在没有内容就放弃“结果必须是另一个列表”的要求。两次使用同一个source调用，应得到两个彼此独立的结果，source一直保持原内容。

这不是去重任务。`append_note('echo', ['echo'])` 应保留两份echo，空便签也占一项。把集合加入实现会无故丢掉重复内容与顺序。

外层复制只隔离列表本身。若列表元素将来是字典，两个外层列表可能仍指向同一份内部字典。这些例子中的便签是文本，不需要把深复制当成所有复制问题的默认答案。先问哪个对象可能被谁修改，再决定复制边界。

## 检查返回之后会不会变化

保留第一次结果，然后做第二次调用，观察第一次结果是否仍为原样。再把显式输入source保留下来，分别调用两次，检查三个列表的内容与身份。只比较第二次返回内容，可能错过第一份结果被改坏的问题。

## 为多位访客建立独立的待办页

新函数接收一个“访客名到待办列表”的字典，为其中一位访客追加事项，返回新的字典。调用者的原字典和被修改访客的原列表都不能变；没有变动的其他访客列表允许共享。若访客不存在，创建新列表。

这次只复制外层字典还不够。先画出字典指向各列表的关系，明确哪一层需要新建。测试两个访客、重复事项、原先空列表以及连续修改同一访客，保留所有旧返回值再比较。

这道迁移由你人工核对，重点是有选择地复制发生变化的部分。当前单列表任务通过不会自动证明嵌套结构已经隔离。
