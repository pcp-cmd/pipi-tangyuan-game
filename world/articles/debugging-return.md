# 返回以后，下一轮不会再发生

起始程序处理 `[2,-1,5]` 没有报错，却只交回2。总数变量的加法可能没写错，问题是函数在看完第一项后已经结束，后面的-1和5没有机会影响结果。

你已学过分支、循环与局部变量。缩进说明一条语句属于哪个代码块；return结束整个函数调用，不是结束当前一轮。要判断它是否过早，先问“交回结果前，哪些输入还没看过”。

## 用访问轨迹确认代码走到了哪里

在普通Python中运行一个有相同控制流错误的检查器。

```python
def inspect_first(values):
    seen = []
    for value in values:
        seen.append(value)
        return seen

print(inspect_first([4, 8, 9]))
print(inspect_first([]))
```

输出 `[4]` 和None。非空输入第一次循环就return；空输入连循环体都不进入，函数走到末尾，没有显式return时交回None。这两个结果分别揭示“太早返回”和“某条路径没返回”，不能只补其中一个。

本课 `positive_total(values)` 只累加严格大于0的整数，最后返回整数。先在纸上写 `[2,-1,5]` 的状态：开始0，处理2后2，处理-1后仍2，处理5后7。将每轮实际轨迹对上这张表，确定返回发生在全部输入处理后。

## 返回位置与筛选条件分别检查

把返回移到正确位置后，还要确认条件确实是大于0。0不改变和，但它不能让循环提前停止；负数应跳过而不是把总数归零。`[-4,3,0,9]` 应累计12，特别适合查看负数在首项时是否还有后续处理。

空列表与全非正列表都应返回整数0。不要用None表示“没有正数”，题目已经规定了加法的空结果。也不要排序或删输入里的负项，筛选累计可以只读取原列表，不必改变调用者的内容。

一种修法在if分支内return，只有碰到正数才返回，依旧只完成局部任务；另一种在for内部return total，即使值不正也会结束。检查缩进时把“何时改变total”和“何时交出最终total”作为两个独立问题。

## 让累计同时说明用了哪些项

另实现区间筛选汇总，输入整数列表及low、high，只累计满足 `low <= value < high` 的项，同时返回这些项的原始索引。low大于等于high时没有命中。

用首项不合格、后面连续合格、最后一项合格以及全不合格来检查遍历完整性。核对和与索引指回的值相符，输入不变。新题增加双边界和位置证据，不能只替换大于0条件就算完成。由你保存逐轮状态与结果人工核对，不自动记成绩。
