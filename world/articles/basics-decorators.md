# 给报价函数戴一枚标签：装好包装，等真正调用

皮皮有几台报价函数，想在结果旁边标明“试算”或“正式”。如果每个函数都加一遍标签逻辑，计算规则与展示规则会缠在一起。装饰器允许在函数外面加一层可调用的包装：原函数仍负责原计算，包装层安排额外行为。

先确认你会把函数作为值传递，也会用闭包记住外层变量。调用参数也很重要：`*args` 收集位置参数，`**kwargs` 收集关键字参数；把它们放进调用表达式时，则把收集的参数展开。丢掉其中一种，就可能让原先合法的报价调用失效。

## 定义时装好，调用时才工作

普通装饰器接收函数，返回一个可调用对象。写 `@decorate`，等价于函数定义以后再执行 `function = decorate(function)`。如果装饰器还需要标签配置，就多了一步：先接收标签，制造出能接收函数的装饰器，最后才轮到真实业务参数。

本课因此有三个时刻：配置时知道标签，装饰时知道原函数，调用时才知道这一次的货物参数。不要在前两个时刻提前执行报价，那里既没有本次参数，也不应该产生一次外部调用。

下面是另一个用途的简单包装：调用时输出一条提示，原结果直接交回。它没有标签配置层，也不生成本课要求的结果二元组。

```python
from functools import wraps

def announce(function):
    @wraps(function)
    def wrapped(*args, **kwargs):
        print("开始计算")
        return function(*args, **kwargs)
    return wrapped

@announce
def area(width, *, height):
    """矩形面积。"""
    return width * height

print(area.__name__)
print(area(3, height=4))
print(area.__doc__)
```

输出依次是 `area`、“开始计算”、12 和“矩形面积。”。元信息仍能让工具识别原函数；`height` 这个关键字参数也正确传到了计算中。`wraps` 帮忙保留名称、文档等信息，不负责执行业务或替你添加标签。

## 包装不能悄悄替换原来的东西

本课 `label_result(label)` 创建装饰器。被包装函数每次接收任意原位置与关键字参数，原函数恰好调用一次，最后返回 `(label, 原返回对象)`。若原函数交出一个列表，结果第二项应是那个列表本身，不是你复制、转字符串或重新构造的近似内容。原返回值为 `0`、`False`、`None` 也一样，不能因为是假值而丢掉。

原函数抛错时，传播同一个错误对象，不转换成 `("失败", "错误内容")`，否则调用者原本的异常处理就被绕开了。保留名称和文档也属于合同；包装函数叫 `wrapped` 并不意味着对外也应该丢掉原来的名字。

具体反例是包装里写 `function()`：无参例子也许通过，真实函数需要 `amount` 或关键字 `currency` 时就会失败。另一种反例是在装饰时先算出结果，所有后续调用都重复返回第一次结果。再试两份不同标签的装饰器交错调用，可以揭穿用同一个全局变量存标签造成的串改。

本课练的是普通同步函数的包装。异步函数、描述符方法以及复杂属性复制有各自额外约定，不会因为套上 `wraps` 自动全部正确。

## 独立任务：记录一次调用的成功或失败

写一个可配置日志列表的装饰器。实际调用开始时追加 `"start"`；原函数成功则追加 `"success"` 并交回原对象；抛错则追加 `"failure"` 并继续传播同一个错误。每次原函数只调用一次，装饰阶段不能写调用日志，两份装饰器各写自己的列表。

这次装饰器不改变返回值形状，而要围绕成功与失败记录事件。用需要关键字参数的函数、返回空列表的函数、抛出预先创建错误的函数分别测试，核对事件顺序、对象身份、元信息和两个日志的隔离。需要自行运行并解释异常路径；当前课题的标签检查不会替这份日志装饰器判定。
