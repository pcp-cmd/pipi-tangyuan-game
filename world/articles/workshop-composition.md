# 串起三个加工站

货箱先去掉潮湿标签的首尾空格，再把编号字母改成小写，最后交给登记台。各加工站只做好自己的那一步，前一站输出正好成为下一站输入。次序一变，可能就不是同一件事。

本课实现 `pipeline(value, operations)`，按顺序把value送过每一个函数，每个函数恰好调用一次。空operations返回原值。某阶段抛出异常时，原样传播该异常，不执行后面的阶段。

## 传的是刚刚得到的结果

先比较两个算术站的次序。

```python
def add_two(value):
    return value + 2

def times_four(value):
    return value * 4

print(times_four(add_two(3)))
print(add_two(times_four(3)))
```

输出为20与14。函数名一样、起点一样，调用顺序不同，结果就不同。完整pipeline需要记住每一站实际交回的值，不能每次都把最初value送进去。

operations里放的是函数值，取出一个函数不等于已经执行。先调用它一次，再把结果交给下一站。为了打印调试而额外调用一次，会重复业务效果，也会违反当前“恰好一次”的约定。需要观察时保存那一次的结果，再打印保存的值。

## 0和None都能继续流动

某个加工站可能把输入转换为0、False、空字符串甚至None。这些都是实际结果，不能用“如果结果为真才继续”决定下一步。后一个函数可能专门接收None，再转换成另一个对象。

空流程则没有任何转换，应该返回同一个原对象。若起点是字典，不要为了“统一输出”偷偷复制一份；如果起点是假值，也不能换成缺省结果。

组合还要求接口相容。上一站输出整数，下一站若只接受字符串，就会抛出类型相关错误。pipeline负责顺序传递，不应猜测该替下一站做什么转换，否则每个阶段的合同都变得模糊。

## 失败之后不能继续加工

让第二站抛出你事先创建的异常对象，第三站只要被调用就往列表写一条记录。运行后，调用者应收到原异常对象，第三站的记录为空。不要捕获异常后返回None继续下一站，也不要把异常重新包装成只有相同文字的新对象。

停止后续调用不等于回滚前序效果。若第一站已经写了文件，第二站失败不会自动恢复文件。当前题的异常传播不提供事务，具有外部效果的组合需要另外设计保存与恢复边界。

## 保留每站的观察，但不重复执行

新任务返回最终结果及一份轨迹，轨迹记录每个阶段的序号、输入和输出。阶段失败时，把此前成功阶段的轨迹交给调用者，同时仍保留原异常供其处理。你先决定用什么接口同时表达轨迹与失败，不能靠把异常变成普通成功值来凑格式。

用带调用计数的函数检查每站仍恰好一次。再测试空流程、None中间值、第二站失败以及输入输出是同一可变对象的情况。解释保存引用与保存快照会造成什么不同，并明确自己的轨迹合同。
