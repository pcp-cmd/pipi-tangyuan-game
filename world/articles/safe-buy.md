# 买得起才出发

售票员不该只回答今天的皮皮能不能买票。换一位旅客、换一个票价，同一条规则仍要管用。钱比票价多可以购买，刚好相等也可以，钱少则不行。本课让 `can_buy(coins, price)` 交回这个判断，不实际扣钱。

在写条件前，先看清函数是什么。`def` 给一段可以重复调用的步骤取名字。括号里的名字是参数，调用时传入的值会成为这次调用的输入。冒号后的缩进区域是函数体，Python通常用4个空格缩进。

## 显示一句话与交回一个值

下面的函数只判断一段标记是否为空，与购买规则无关。它可在普通Python运行。

```python
def has_label(text):
    return text != ""

answer = has_label("北门")
print(answer)
print(has_label(""))
```

输出为 `True` 和 `False`。`!=` 比较两边是否不同，结果是布尔值，也就是程序使用的真或假。`return` 把结果交回调用处，`answer` 才能保存它。调用函数时，函数体才执行。

若把函数内的 `return` 改成 `print`，屏幕会出现文字，但调用处拿到的是 `None`。调用者需要根据结果继续行动，不能从终端上的一行字取得可靠返回值。字符串 `"True"` 也不是布尔值 `True`。

`>` 只包含“大于”，`>=` 还包含“等于”。先用数轴画出余额少1、恰好相等、多1的三个位置，再选择能覆盖购买规则的比较。这一步比对某一笔交易反复试错更有用。

## 看三位旅客，而不是记一个答案

当前函数有两个输入，每次调用各自使用那次的值。不要在函数里再固定成今天的钱数或票价，也不要根据谁来调用挑结果。

例如余额40、票价40，若程序用严格大于判断，就会误拒绝。余额39、票价40必须拒绝。把差额直接返回也不行，差额是整数，本课要求真正的布尔值。即使差额1在条件中被视为真，它也不等于按接口要求交回 `True` 这件事。

这里处理非负整数余额与价格。0金币购买0金币的票也符合“余额足够”。课堂没有要求支付、库存预留、负数输入校验或并发扣款，不要把一个比较函数叫作完整交易系统。

## 票买得起，船也未必能登

设计另一函数，接收余额、票价和“是否持有预约”的布尔值。它返回一句原因文字，而不是布尔值。先检查预约，没有预约时返回“需预约”；有预约但钱不足时返回“余额不足”；两项都满足时返回“可登船”。

先列四种预约与余额组合，并加入余额恰好等于票价的情况。特别说明既无预约又缺钱时，为什么应按规则返回“需预约”，不能随机选一个原因。

这次增加了第二项输入条件、固定的检查优先级，以及三种文字输出。先把决策顺序用自己的话写出，再写程序。需要按条件选一条语句时，可用 `if 条件:` 开始一个分支，把该分支的返回语句缩进4格。条件为假时，程序会继续执行分支之后的语句。用独立文件保存测试和结果自行核对，它不会自动记入本课成绩，也不能证明你已经实现真实购票。
