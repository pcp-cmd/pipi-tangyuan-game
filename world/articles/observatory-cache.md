# 命中旧结果之前，先问它属于谁

同样查询“潮汐”，皮皮可能看到自己的航线，汤圆看到另一条。数据更新后，同一个人的同一句查询也应重新计算。如果缓存只用查询文字当键，程序可能很快地返回别人的或旧版本的公告。

缓存是保存计算结果以便复用的地方；键是用来决定“这次请求能否用那份旧结果”的身份。键中漏掉任何会影响结果的条件，都会把本该不同的请求合并。当前课只构造键，不实际读写缓存，也不替你制定超时淘汰规则。

## 把结构留在结构里

普通Python中，两份不同参数用简单字符串拼接，可能变成同一字符串。

```python
left = ("ab", "c")
right = ("a", "bc")
print("".join(left) == "".join(right))
print(left == right)
print("  Sea  Map  ".strip())
```

输出True、False、`Sea  Map`。元组保留每项的边界，比较时逐项比较；无分隔拼接丢掉边界，无法区分两种拆法。即使加分隔符，若内容里也允许该符号，仍需要可靠的编码规则。

本课要求返回三元素tuple，依次保留user、version以及处理后的query。不是字符串，也不是列表。把用户或版本省掉，即使当前样例只见一个用户，也会在数据变化时出错。用户相同、查询相同而版本不同，必须能形成不同的键。

## 清理的范围也是业务规则

query只去首尾空白。`' tide  map '` 变成 `'tide  map'`，内部两个空格保留；`' TIDE '` 保持大写；全空白文本变成空字符串。这不等于lower、split再join或删除所有空格。对当前任务来说，大小写或内部空白不同仍是不同请求。

用户与版本按输入保留，不要为“统一格式”自动转字符串。做排错时一次只变一个维度：变用户、变版本、变查询正文，然后再试只加首尾空白。前三种应按合同区分，最后一种应归到同一个查询身份。

键足够完整也不保证缓存永远正确。计算还若依赖语言、权限或配置，它们也可能需要参与身份；但不要把未知条件硬塞进当前三元组，先改变接口约定才有地方携带这些值。失效策略同样是另一件事：版本更新能区分数据，旧条目何时释放仍需缓存管理者决定。

## 给语言与权限一起建边界

另设计报告缓存，结果依赖用户、数据版本、查询、界面语言和权限版本。先列出每个字段允许怎样规范化，再设计能稳定比较的结构。查询首尾空白可忽略，语言代码按明确约定规范化，用户和权限版本不得丢失。

准备只改变一个字段的请求对，写出哪些应命中同一条、哪些必须隔离，并构造一个分隔字符串碰撞反例。再说明权限版本改变后旧结果为何不能复用。这个任务增加结果依赖维度和规范化责任，需人工审查设计，当前游戏不会自动验收。
