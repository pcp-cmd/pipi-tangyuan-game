# 报错发生在队尾，原因可能在范围右边界

起始程序想把第一件物品挪到最后，却在运行两项列表时抛IndexError。先别把异常捕获后忽略。没有报错并不等于每件物品都还在；我们要找出第一次越过列表范围的位置。

你已经用过切片和输入检查。列表长度为n，非空时索引从0到n-1。`range` 的右端不包含在结果中，因此写哪一个右端决定循环最后访问哪一格。工作台的起始代码把范围写到 `len(values)+1`，先在游戏运行它，读报错行并对照当前index。

## 把范围列出来，看见多出来的一格

下面的普通Python探针只观察越界，不是修复函数。

```python
values = ["lamp", "rope"]
for index in range(1, len(values) + 1):
    try:
        print(index, values[index])
    except IndexError:
        print("越界索引", index)
```

输出 `1 rope`，然后是 `越界索引 2`。长度2不是最后合法索引；循环已经取到rope，还要去取不存在的第三格。本例捕获异常是为了显示发生的位置，提交的修复不能靠跳过所有IndexError来掩盖范围错误。

当前目标 `shift_left(values)` 应返回新列表，把原第一项移到末尾，其他项次序保持。可以从循环的右界推理，也可以用切片描述前后两部分，但必须保留每一项。仅删掉报错行可能消除异常，也可能把队尾一起删掉。

## 空列表暴露第二个问题

修好循环上界后，空列表仍没有values[0]。这是与队尾越界不同的第二条路径，必须明确处理。空输入返回新的空列表；单项返回内容相同的新列表。不要为省事在长度小于2时直接return输入，因为调用者随后改返回列表会连原件一起改。

用两项看旋转方向，用三项看中段是否遗漏，用 `[0,False,None,'',0]` 看是否错误过滤了假值或重复项。旋转不是筛选，值是否为真不参与保留决定。输入本身不应被pop、append或重新排列。

最后核对长度不变、每项出现次数不变、顺序只发生一次左移，以及返回对象不是原列表。内容相等与对象独立是两项证据，特别在空列表和单项时容易只测到前者。

## 把旋转数量也作为输入

另实现按k次左移的非原地旋转，k允许任意整数；正数左移，负数右移。输出始终新列表，空输入无论k为何值都返回新空列表。

先手算长度3时k为0、1、3、4、-1的结果，解释如何用余数减少重复工作。再检查不能在空列表上先求模除以0。新题改变移位数量与方向，原先只移动第一项的做法不能机械复制。保存结果和身份检查，人工验收不自动写入成绩。
