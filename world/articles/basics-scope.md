# 每次调用各有一张草稿

上午的补给加总用了起始库存10，下午另一艘船从0开始。若两个计算共用一个不断增加的全局总数，下午会莫名继承上午的货。你要让每次调用都从这次的起点重新计算。

`running_total(values, initial=0)` 接收一份数值列表与可省略的起点。省略时使用0，空列表则直接得到起点。它不能改变列表，也不能让上次调用的累计状态流进下一次。

## 相同名字，不等于同一轮计算

在函数里赋给普通名字的值，通常属于这次调用。能够通过某段代码中的名字找到值的范围叫作用域。先看一个普通Python小例，它只计算下一个编号。

```python
number = 50

def next_number(number):
    number = number + 1
    return number

print(next_number(3))
print(next_number(3))
print(number)
```

输出4、4、50。两次调用各收到3，不会把第一次的4当成第二次输入。函数内参数的重新赋值，也没有改掉外面的同名整数50。

整数不能在原位置改成另一个整数。`number = number + 1` 先产生新值，再改变本地名字指向。列表则可以原地修改，所以“变量在函数里”并不自动意味着“调用者的数据不会变”。若对传入列表执行append或删除，调用者也能观察到变化。

## 起点属于本次输入

先用 `values=[2, 3]`、起点10追踪，本次累计从10走到12再走到15。紧接着处理 `[1]` 且不传起点，应得到1，而不是16。重复同一调用也应给出同一结果。

`initial=0` 表示默认参数，调用处可以传第二个位置参数，也可以写 `initial=9`。默认整数不会像可变列表那样被append累积；这里不需要把默认值搬到外部长期保存。

避免从列表中反复pop以驱动循环。那虽然可能算对一次，却把调用者原始记录消耗掉。另一个常见错误是每次都从0开始，从而忽略传入的initial；空输入最容易暴露它。

## 同一批货，问两种起点

另写一个函数，输入同一份数值列表与若干起始库存，返回每种起点对应的最终总量列表。各个结果彼此独立，两个输入列表都保持不变。

先用货物 `[2, -1]` 和起点 `[0, 10, 0]` 预测结果，重复起点必须重复得到相同值。再试没有货物、没有起点两种空输入，它们的输出含义不同。

新题从一次调用扩为多次独立计算，并新增第二份输入的保留责任。保存调用顺序和结果，检查交换起点顺序只交换对应结果，不改变数值。迁移题由你自核，原课通过不能证明跨调用状态都已理解。
