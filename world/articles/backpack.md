# 整理两只猫的背包

皮皮把鱼饼放在背包最上层，水壶在后面。临走时汤圆递来地图。你要把地图加在末尾，并记住第一件物品。若把背包重新写成一份固定清单，遇到装着指南针的旅客，就会把人家的东西换掉。

你已会让名字指向一个数。名字也可以指向一串按顺序摆放的值。用方括号把这些值围起来、用逗号分开，就是列表。列表保存顺序，也允许内容改变。

## 加一件东西与拿到一件东西

普通Python中的候船队能说明这两个动作。先读代码，预测每一行输出。

```python
queue = ["阿青", "小满"]
added = queue.append("阿海")
print(queue)
print(added)
print(queue[1])
```

输出依次是 `['阿青', '小满', '阿海']`、`None`、`小满`。`append` 在已有列表末尾添一项。点号前面的 `queue` 指出修改哪份列表，括号里是新增的值。它做完修改后交回 `None`，没有交回一份新列表。

因此 `queue = queue.append("阿海")` 会把名字改为指向 `None`。名单已被修改，但这个名字不再指向名单。看到后续“不能按下标读取None”的错误，应回查上一次赋值，而不只盯着报错行。

`queue[1]` 则只是读取位置1，不会从队伍里移走小满。位置编号叫索引，从0开始。三件东西的索引是0、1、2，长度3不是最后一个合法索引。

## 背包变了，位置规则没变

工作台的 `bag` 是输入。要求在它原有内容后添“地图”，让 `first_item` 从最终列表的第一格取得值。初始背包非空，加入地图后也非空。检查会更换原有物品，所以把 `first_item` 写死成“鱼饼”不能代表读取第一件物品。

拿 `['指南针', '绳索']` 在纸上模拟。新增地图后应保留原两项及顺序。第一件仍是指南针。若你把地图放到最前，虽然“列表里有地图”成立，顺序约定却已经变了。

列表允许重复值。背包本来有地图时是否还加一张，是业务规则，不能由 `append` 猜。当前任务要求添一项，并没有“有就跳过”的去重规则。空列表读取索引0会报 `IndexError`，这是之后设计通用工具时要另定的边界，不要为了当前非空任务静默吞掉所有错误。

## 给两只猫各办一张行李签

另用普通Python建立两份独立的非空行李列表。给皮皮末尾加一件雨具，只打印汤圆原有的第一件物品，确认汤圆的名单没有增加雨具。然后把任务改为“保留原名单，再另做一份带雨具的出航名单”。

先观察 `departure = original` 后修改 `departure` 会发生什么，再用 `original.copy()` 从原列表取得一份浅复制。这里只使用字符串物品，不包含嵌套列表。请解释两种操作是让两个名字指同一份列表，还是创建另一份列表。

自核时保存修改前后两份名单、首项与长度，证明原名单确实保持原值。这题新增了“两个容器是否共享修改”的责任，不是只换追加物品的名字。原课通过不会自动验收这项练习。
