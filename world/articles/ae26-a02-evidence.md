# 回答之外的运行记录

助手说“已经查过船期”，汤圆打开查询账本却发现一次调用都没有。最终回答只是一份返回值，要判断程序真正做了什么，还需要在动作发生处留下记录，并用工具自己的记录核对。

本课在上一课run的行为上增加两部分。`run_traced(model, tools, max_steps=3, events=None)` 保持原预算与返回合同，在真实步骤旁追加事件。`append_event(write_line, event)` 把允许的字段编码成一行JSON，调用受控追加器一次。

## 事件应跟着真实动作出现

有效运行开始记录run_started。每次调用model之前记录model_called。合法工具建议记录tool_requested；只有工具已登记、即将实际调用时，才记录含工具名的tool_started。工具返回后记录tool_completed，OSError发生后记录tool_failed。已知结束记录run_stopped与status。

这些名字表达的是不同事实。未知工具可以被请求，却没有真正开始，因此不能出现tool_started。工具调用抛错，就不能再补一条tool_completed。其他程序异常需要原样传播，此时不要伪造一个正常的run_stopped。

无效预算必须在写任何事件之前拒绝。否则记录会说任务已经开始，而本次输入其实还没被接纳。

## 调用者传来的空列表仍属于调用者

events为None表示调用者没有提供容器，这时才创建新的列表。调用者主动给了 `[]`，程序必须向这份列表追加，不能用“空就重新建一个”的写法换掉它。也不要把空列表写成函数默认参数，那份列表会在定义时创建，可能被多次调用共用。

本课只追加实际发生的事件，不修改已有事件。测试时把一条已有记录放在列表前面，确认它还在；连续运行两次，也要分清新创建的容器与显式共用的容器。

## 一行JSON怎样保存内部换行

JSONL要求每行是一个完整JSON值，行尾换行分隔记录。字段里的换行交给JSON编码器转义，不能先把字符串中的换行直接拼进去。

```python
import json
record = {"event": "note", "text": "第一行\n第二行"}
line = json.dumps(record, ensure_ascii=False) + "\n"
print(len(line.splitlines()))
restored = json.loads(line)
print(restored["text"] == record["text"])
```

输出为 `1` 和 `True`。编码后的物理记录只有一行，读回后仍保留原字段中的换行。不要用字符串相加手写JSON，遇到引号与反斜线很容易产生无法读回的文字。

本课append_event要求run_id与event都是非空字符串；可选tool和status如果存在，必须是字符串。只保留这四个字段，另建待编码字典，不修改原event。坏事件抛ValueError并零写入，追加器抛错则保留原错误。write_line是本次传来的函数，不是任意文件路径。

字段白名单减少无关记录，但不保证允许字段里没有私密内容。真实系统仍需要选择应该记录的值。游戏这里使用合成资料，真实文件追加、关闭和失败恢复在文件课程与工具桥工程中继续练。

## 完成声明还需要另一份观察

让一个model直接返回“已经查过”，它可以使循环completed，却不会凭空产生工具调用。再让真正的工具记录自己的调用次数与返回值，与你的事件列表对照。只有靠近动作的记录与独立观察一致，才有理由判断动作发生过。

原生工具桥工程会把请求配对、子进程日志和实际效果分开核对；可复查研究工程还检查资料来源与版本。[仓库交班](../integration/external-stockledger/README.md)则要求你从真实 CSV 生成库存报告，在交付说明中写出实际解释器、命令、退出状态，补自己的测试并证明坏输入不会破坏旧报告。下载、保存材料、本地自测与可信审核是不同步骤，课堂通过不等于工程毕业。

## 给一次重试保留两次尝试

新任务记录一个操作的多次读取尝试。每条记录要有operation_id与attempt，attempt从1递增；失败后重试仍属于同一操作，成功只结束该次操作。先定义“尝试开始、尝试失败、尝试成功、操作停止”的事件格式，再写记录器。

用第一次OSError、第二次成功的受控读取器做实验。检查两次尝试都可见，编号连续，成功没有抹掉失败，写日志失败也没有被吞掉。再让所有尝试失败，明确最终状态。

迁移题是人工核对，改变了身份与重试层次。它不自动接入游戏成绩，也不要求真实外发操作。保存原始记录与读取器自己的计数，而不是手工补一份看起来完整的日志。
