# 找中间读数，还要保护计算中间的数

传感器读到1、2、99，平均值被99拉高，中位数却是排好序后居中的2。另有None表示没有读数，它应该被跳过；真实读数0仍要留下。先把缺失与数值分清，再谈怎样找到中间。

输入是有限的int、float或None，不含bool、NaN或无穷。过滤条件应是“不是None”，不能用 `if value`，否则0会消失。有效值排序后，奇数项取中间一项，偶数项取中间两项的平均；没有有效值返回None。

## 同一个平均式，可以在中途失真

下面在普通Python中只看中点计算的两个反例。

```python
import math

large = 1e308
small = 5e-324
print(math.isfinite((large + large) / 2))
print(small / 2 + small / 2 == small)
print(small == small)
```

输出False、False、True。两个有限大数先相加会得到无穷，即使正确平均值仍有限。改成各自除2再相加虽避开这一溢出，却会把最小正次正规浮点数的一半舍入为0。次正规数是极接近0的一段可表示浮点数，这里只需知道“非零小数也会在中间步骤变零”。

因此不能只把一种平均公式换成另一种就声称覆盖全部输入。若两端相等，直接保留该值能避开不必要运算；若不等，可以用整数比保存它们的精确值，再安排平均与最终输出。

## 整数比先保存值，最后才决定表示

一个整数可写成它本身除以1。有限float的 `as_integer_ratio()` 返回两个整数，它们的比恰好等于这个浮点对象已有的值。若两端分别是a/b与c/d，中点是 `(a*d+c*b)/(2*b*d)`；分子分母都用整数计算，就不会在求和阶段丢失微小项或把大整数强转为无穷。

整数比不是把0.1恢复成理想十进制十分之一，而是保留计算机当前存着的二进制值。本课允许int或float数值结果，以相对1e-9或绝对1e-12容差比较，但极小数相等等检查仍需保留正确边界。返回Fraction对象不是题目承诺的结果类型；整数比在这里是内部计算方法。

先用整除与余数判断中点能否精确表示为整数；需要小数且可表示时再做除法。若中点大到超出float范围，保留一个相差小于1的整数近似，在这个巨大量级远小于允许的相对误差。不要在分子消去之前把巨大正负整数各自转float：`-10**400` 与 `10**400+1` 的中点仅0.5，先转换反而失败。

排序和数值处理是两层。可以用排序索引或median_low、median_high取得两端，仍须自己负责平均的边界。直接调用普通median不等于已满足本课大数约定。自测至少覆盖0与None、偶数项、两相等极小数、同号巨大浮点与巨大整数抵消。

## 同时报告中心与缺失比例

另写一份传感器摘要，输出有效数量、缺失数量、中位数以及“距中位数超过阈值”的原始索引列表。缺失项不参与排序，但索引仍按原输入定位。

让有效读数顺序被打乱、其中有0和None，再用极大相等值检验中心计算。检查排序位置没有被误当原索引，阈值边界是严格超过，输入保持不变。新题组合计数、稳健数值和原位置追踪；结果需自行核对，不自动记入游戏成绩。
