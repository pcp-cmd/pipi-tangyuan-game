# 工具门口的登记台

移动工具原本只收一个步数，传来的字典却多出 `admin=True`。程序若一边忽略陌生字段，一边把整份字典交给后续工具，就无法说清究竟批准了什么输入。登记台需要先限定请求的形状。

本课实现 `valid_move(args)`。只接受字典，而且恰好有steps这一个键。对应值必须严格为整数1至6，布尔值不算。函数返回True或False，不发出移动指令。

## 容器、字段、类型、范围要逐层确认

先确认args是字典，才能安全检查键。随后检查键的集合是否恰好符合要求，再看steps的类型，最后看数值范围。这个顺序避免在列表或None上读取字段，也避免把不合法文字先拿来比较大小。

观察一个与移动无关的登记表。

```python
request = {"label": "灯塔", "copies": 2}
print(sorted(request))
print(set(request) == {"copies", "label"})
print(type(request["copies"]) is int)
```

第一行显示排序后的键列表，随后两行都为True。排序只用于让示例显示稳定；集合相等本身关心成员，不关心键写入的顺序。本课实际判断也不应依赖字段排列。

只检查 `"steps" in args` 还不够，因为 `{"steps": 2, "admin": True}` 同样含steps。字段数量也不能独自证明名称正确，一个名为distance的键虽然也是一项，却不是本课接收的字段。

## 看起来像整数的值也可能不合格

`2.0` 与2在数值比较中相等，但它是浮点数。`"2"` 是字符串。True属于bool，而bool又是int的子类，所以宽泛的isinstance整数检查会接受True。当前合同要求严格整数，应先按这个要求区分，再检查范围。

边界1与6都允许，0与7拒绝。若写成严格小于6，会错拒绝端点；若用真值代替范围检查，负数也可能被当成“有值”。把0、1、6、7并排写下预期，比只试3更容易发现边界错误。

这层检查不会把 `"2"` 自动转成2，也不会删除admin字段后继续。修正输入应由调用者有意识地完成，校验函数负责如实回答原输入是否符合约定。

结构与数值合法仍不代表有权移动。下一课检查谁批准、批准哪份参数以及有效时间。本课不接真实外部操作，也不把一份合法字典视为权限凭据。
