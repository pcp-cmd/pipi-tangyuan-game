# 让 Agent 选对工具

汤圆想知道鱼饼价格，皮皮却直接拿起了付款单。看见一句请求就执行最接近的动作，会把“先看看”误当成“现在买”。程序需要先选出下一步，再由后面的代码决定这一步能不能执行。

本课实现 `choose_tool(intent)`。收到恰好为 `"查价格"` 的文字，返回 `"search"`；收到 `"购买"`，返回 `"buy"`；其他输入返回 `"ask"`。返回值是一个行动名称，本函数不读取价格，也不购买物品。

## 名称怎样对应能力

前面的价目表用键查价格，函数课介绍了参数和返回值。这里沿用这两个知识，但字典里的值可以换成行动名称。先观察一个码头标识表。

```python
signs = {"候船": "waiting_room", "寄信": "post_office"}
print(signs["候船"])
print(signs.get("问路", "help_desk"))
```

输出是 `waiting_room` 和 `help_desk`。第一行查到已知标识，第二行使用约定的缺省去处。`get` 的第二个参数只处理找不到键的情况，不会判断新文字与已有文字是否意思接近。

你也可以用条件分支表达这个选择。无论采用哪一种写法，都要明确哪些输入被承认，哪些输入需要追问。不要用最后一个 `else` 默认为购买，这会让所有未预料到的请求都产生同一个动作。

## 精确匹配的好处与限制

本课比较的是完整字符串。`"购买全部"` 虽然包含“购买”，仍不在已知请求中。`"SEARCH"` 也不是 `"查价格"`。空字符串没有给出意图，应走追问路径。

如果写成“包含某个字就购买”，你自行扩大了接口的含义。例如“不要购买”同样含有“购买”。本课不要求理解自然语言的否定，也没有真正的模型替你辨认意思，因此默认追问比猜一个动作更符合当前合同。

返回 `"buy"` 也不代表获得了购买许可。路由回答“该交给哪种能力”，许可检查回答“现在允许执行吗”，两者必须先后衔接。下一课会单独处理许可，未知名称也不能绕过那层检查。

这里的 Agent 练习是一段确定性程序，输入相同就按相同规则返回。它让你看清工具选择的位置，尚未涉及模型的推理质量、工具调用失败或真实支付。

## 为码头做一个不会猜的分流台

另写 `route_ticket(ticket)`。输入改为字典，必须同时有 `department` 和 `urgent`。已知部门是 repair 与 mail；urgent 必须是布尔值。普通维修送到排队处，紧急维修送到值班处，邮寄不分紧急程度都送到邮局；缺字段、错误类型和未知部门统一送到人工询问处。
