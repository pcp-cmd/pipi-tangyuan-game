# 多一份字典，还不等于多一份补给

汤圆要在每只猫的补给记录末尾加上今天的数量，但旧账还得留给皮皮核对。外层字典复制了，里面的数量列表却可能仍是原来那几份。新账一动，旧账也变，这不是加法错误，而是两份账仍指着同一份可变内容。

你已见过列表追加和字典按键读取。这里多问一层：字典的值是什么？本课值是整数列表。名字、字典条目与列表之间保存的是引用；赋值让另一个位置引用对象，并不会自动复制对象。

## 顺着引用找到实际被修改的一层

下面是普通Python中的浅复制反例。

```python
original = {"pipi": [2]}
outer_copy = original.copy()
outer_copy["pipi"].append(5)
print(outer_copy is original)
print(outer_copy["pipi"] is original["pipi"])
print(original)
```

输出 `False`、`True`、`{'pipi': [2, 5]}`。两个外层字典确实不同，但它们的pipi值仍是同一个列表。`is` 判断是否同一个对象，`==` 判断内容是否相等。只检查外层 `is` 就宣布复制完成，会漏掉真正发生修改的内层。

本课 `resupply(supply, amount)` 需要新外层字典，也需要每个名称对应的新列表。整数本身不会被追加操作改写，因而只要在列表这一层建立独立内容，无需把整数逐个深复制。你可以先复制某个列表再追加，或者用产生新列表的操作组合旧项与新增项。

## 把外部持有的旧列表也算进来

调用者可能先保存 `saved = supply['皮皮']`。你的函数若先原地加数量，再把字典值换成一份新列表，字典最后看似正确，但 `saved` 已经看见了不该发生的变化。因此“不改输入”包括原字典和原列表整个过程里的可观察修改，不能靠最后恢复表面值掩盖。

若两个输入名称本来引用同一份列表，逐项创建新列表会让输出的两份记录也能分别修改。这是本节建议的复制策略。当前任务明确要求保护原字典与原列表；输出之间是否保留输入原有的共享关系，在更一般的接口里还需另行约定，不能把更强的隔离要求当作既有检查已验证。空字典也应返回新字典；空列表加一次补给后应有且仅有这一项。不要用真值判断把数量0当作“没补给”。

排错时保留旧外层、旧内层和输出各一个名字，分别比较内容与身份。单看打印值相同无法证明独立，因为两个新列表和同一个旧列表可以打印得一模一样。

## 复制计划，保留共享说明

另设计旅行计划，字典每项含一个可变的 `days` 列表和一个只读说明字符串。复制整份计划，在新计划的每个days末尾加一天，同时允许说明字符串继续共享。再让两个输入行共享同一days列表，验证输出行能分别改动。

检查新外层、新内层、原列表外部别名以及新计划之间的关系，并解释哪些对象需要复制、哪些不需要。这次容器多了一层，不能只套一次字典copy。用身份检查和修改后检查一起自核；它不由当前自动判题验收。
