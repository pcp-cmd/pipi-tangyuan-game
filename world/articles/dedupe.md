# 一次订单，只付一次

码头的通讯器断了一下，汤圆把同一张订单又发了一遍。收到的编号是 `['b', 'a', 'b', 'c']`。这次整理清单要保留第一次见到的顺序，所以结果应是 `['b', 'a', 'c']`。

本课实现 `unique_orders(ids)`，输入是订单编号列表，练习中的编号可以是字符串或整数。返回每个编号第一次出现形成的新列表。空输入得到空列表，全部相同的编号只保留一项。

## 两份记录各解决一个问题

列表保存“谁先谁后”。集合回答“这个值有没有出现过”。空集合写作 `set()`，不是 `{}`，后者是空字典。

```python
seen_stickers = set()
print("海星" in seen_stickers)
seen_stickers.add("海星")
seen_stickers.add("海星")
print(len(seen_stickers))
print("贝壳" not in seen_stickers)
```

输出依次为 `False`、`1`、`True`。向集合加两次同样的贴纸，只记一份。`add` 修改原集合，不返回一个新的集合；若把它的返回值重新赋给集合名字，下一次查询就找不到原来的集合了。

回到订单，决定保留一个编号时，需要留下它已经出现的事实，也需要把它放到结果列表的队尾。前者帮助后面的重复判断，后者保留第一次出现的先后。自己确定这两个动作在循环中的位置，不要把尚未见过的编号误判成重复。

## 去重不能顺便改变顺序

直接把输入变成集合再转回列表，虽然可能去掉重复，却不能用集合遍历顺序保证原输入的先后。把结果排序同样改变了问题，`['b', 'a', 'b']` 应保留b在前，不能为了整齐改成a在前。

用相邻重复与分散重复分别检查。例如 `['a', 'a', 'b']` 和 `['a', 'b', 'a']` 都只保留第一次a。再用 `[4, 2, 4, 3, 2]` 检查你没有把整数一律转成字符串。

集合要求其中的元素可以散列，字符串与整数适合这里的编号。若输入变成包含商品与数量的字典，不能直接把整个字典塞进集合；需要先决定哪个字段表示同一个订单。这是数据设计问题，不能靠任意转成文字解决。

本课只整理一次调用中的内存列表，没有支付任何费用。程序重启后，临时集合会消失；两份进程同时处理同一编号也可能各自认为没见过。真正的重复执行保护还需要持久记录与不可分开的检查和写入，后面的幂等与可靠派送工程会处理这些情况。

## 找出第一次重复发来的信号

另写一个函数，返回每个编号“第二次出现时”的一次告警，按第二次出现的时间排列。第三次、第四次出现都不再告警。例如输入 `['a', 'b', 'b', 'a', 'b']`，告警顺序应为 `['b', 'a']`。

现在需要区分未见过、只见过一次和已经发出告警，原来的“只要见过就跳过”不够用了。先在纸上逐项记录状态，再选择集合或计数表。自行检查全不同、全相同、数字编号和空输入，解释第二次出现为什么决定输出位置。
