# 转交一次调用，别悄悄改它的意思

码头调度员需要给一次计算贴上“出航”标签，又不该知道业务函数究竟收几项参数。调度员的职责是把整份请求交给业务函数一次，再把标签和结果交回来。少传参数、重复调用、把结果复制成另一份对象，都会改变请求。

你已学过函数组合。位置参数按位置对应，关键字参数按名字对应。定义中的 `*args` 收集多余位置参数成元组，`**kwargs` 收集多余关键字参数成字典；调用中的星号则把容器里的参数展开。这是同样符号在接收与发送两端的不同作用。

## 先看展开怎样保留调用形状

在普通Python中运行一个有两种参数限制的小函数。

```python
calls = []

def describe(value, /, *, unit):
    calls.append((value, unit))
    return [value, unit]

positional = (0,)
named = {"unit": "kg"}
result = describe(*positional, **named)
print(result)
print(calls)
```

输出 `[0, 'kg']` 和 `[(0, 'kg')]`。`/` 前的value只能按位置传，`*` 后的unit只能按名字传。展开保留了这两种位置，而不是把整份元组当作value、整份字典当作下一参数。调用记录只有一条。

本课 `call_with_label(operation, *args, label='trip', **kwargs)` 中，label放在星号参数之后，只能用关键字指定。它属于包装函数，所以不要把它再塞进交给operation的关键字字典。没有传label时用默认标签；显式传空字符串时就保留空标签，不要用 `label or 'trip'` 把合法假值改掉。

## 返回值要保留那一个对象

operation可能返回列表、0、False、None或别的对象。本课要的是二元组，第二项必须是这次调用交回的同一个对象。检查结果是否“有内容”再决定是否保留，会把0或False错误改成失败。为了打印调用一次、为了返回再调用一次，也会让有副作用的业务发生两次。

异常同样属于这次调用的结果边界。operation抛错时，让原异常传播，不能包装成字符串、返回None，或新造一个同文异常。异常对象可能带有调用者需要识别的信息。本课不要求记录失败日志、重试或补偿，随手添加重试会违反只调用一次的约定。

排错时先记录实际收到的位置元组和关键字字典，再检查调用次数，最后用 `is` 查返回对象身份。若一开始就把它们转成字符串，细节会丢失。参数冲突导致的TypeError也应保持可见，不能靠悄悄删键来“修复”。

## 把调用送入批次，但保持一项失败可定位

另做一个顺序执行器，输入多条任务，每条包含task_id、位置元组与关键字字典。成功项保存原结果对象；普通Exception失败项保存原异常对象并继续下一条。每条最多执行一次，结果按任务输入顺序返回。不要捕获KeyboardInterrupt等进程控制异常。

自核时让第二条失败、第三条成功，并让第一条返回同一可变对象。检查顺序、调用次数、结果身份和异常身份。这次增加了逐项失败隔离与继续执行，不能直接把一层标签包装当作批次处理。此题只作独立实践，未接入游戏判题。
