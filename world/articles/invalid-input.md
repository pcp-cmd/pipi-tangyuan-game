# 遇到坏数据也不慌

收款单有时写“12”，有时被雨淋成“喵”。程序不能把坏文字当有效数量，也不必因为这一张单就让整个练习崩溃。本课规定一种有限的恢复方式，字符串能被 `int` 解析就交回那个整数，否则交回0。

这里的0可能表示真的零，也可能表示转换失败。这是当前接口的取舍，不能拿它做需要区分失败原因的正式账目。你已会定义函数、返回值和转换类型，接下来要识别转换失败的时刻。

## 异常从失败的那一步跳出来

一次操作不能按要求完成时，Python可能抛出异常。`try` 包住预期可能失败的操作，匹配的 `except` 接住某种异常。下面仅演示“读取不存在的列表位置”，没有实现整数解析函数。

```python
seats = ["窗边"]
try:
    print(seats[2])
except IndexError:
    print("这个位置不存在")
print("继续登记")
```

输出“这个位置不存在”和“继续登记”。索引读取失败后，不会带着一个假值继续执行原来的print，而是转入匹配的处理分支。处理结束后继续后面的代码。

`int` 不能把字符串内容解析成整数时抛 `ValueError`。本课参数保证是字符串，因此可以围绕整数转换处理这个明确错误。不要用一个包住全部函数的宽泛捕获把拼错变量等程序缺陷也装成0。

## 解析整数比“每个字符都是数字”更具体

`int` 接受两端空白、普通正负号，也接受Unicode十进制数字及合法位置的下划线。普通Python中试这几种写法。

```python
print(int("  +37  "))
print(int("１２"))
print(int("1_024"))
print(int("-٢٩"))
```

输出37、12、1024、负29。调用 `isdigit()` 预判再转换会错过负号、空白与下划线，还可能认可不能按这里规则转换的上标数字。把实际解析器作为规则来源，比自己猜一种更窄的字符规则准确。

下面故意给出坏格式，用普通Python运行会得到 `ValueError`。

```python
int("1__2")
```

两个相邻下划线不是合法分隔。“3.5”是小数文字，当前任务不能先转float再截断成3。“0x10”也不符合默认十进制解析；普通减号 `-` 与数学符号 `−` 不相同。

在 `parse_coins(text)` 内保留负数，不要把负号删掉后转正。空串、坏格式和非整数文本按当前约定交回0。初始代码只覆盖成功转换，仍需你添加失败路径。

## 让失败带着原单据回来

新题改为批量处理字符串，成功记录为 `(原文, True, 整数)`，失败记录为 `(原文, False, None)`，顺序与输入相同。零不能再代表失败，原文也不能丢。

用 `['0', '喵', ' -2 ', '1_024', '3.5']` 写期望，证明0与坏输入可以区分。自核有效负数、合法下划线、空串和两端空白，并保留每项对应关系。这是新增结果形状与错误信息保存的自核练习，没有自动接入本课成绩。
