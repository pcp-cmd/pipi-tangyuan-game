# 坏的一行留下行号，好的一行继续入账

交班日志混着成功、失败、空白和损坏文本。遇到坏行就停止，会让后半夜的有效记录消失；只保留成功行，又会把成功率虚高地写成百分之百。报告既要汇总有效结果，也要告诉接班人哪些原始行需要检查。

本课按物理行读取JSON，每条非空行应恰有name和ok。name必须是非空白字符串，但作为分组键时保留原文；ok必须严格为bool。空白行跳过，坏JSON、字段或类型错误记录从1开始的原行号，再继续下一行。

## 跳过空白不能重编行号

普通Python中先看行号与空白判断，不解析日志合同。

```python
text = '\n{"event":"start"}\n  \nBAD\n'
for line_number, line in enumerate(text.splitlines(), 1):
    if line.strip():
        print(line_number, line)
```

输出 `2 {"event":"start"}` 和 `4 BAD`。行号在过滤之前分配，因此跳过空白后仍能指回原文件。若先删空行再enumerate，BAD会被报成第2行，接班人查错位置。

每条JSON单独解析，坏一条只影响这一条。JSON字符串内部的转义换行 `\n` 仍是该行文本的一部分；真正的物理换行把记录隔开。不要把整份日志当成一个JSON数组解析，也不要先把多行拼在一起猜缺失括号。

## 失败也属于总次数

有效name第一次出现时建立passed和total两项计数。每个有效行都让total加一；ok为True时才让passed也加一。False不会让整条记录失效。对同名一真一假，结果应是passed1、total2，不能得到1与1。

JSON中的数字1不是布尔True，虽然Python比较时两者可能相等；应检查严格bool类型。额外字段、缺键、数组顶层、全空白name都算坏行。名称 `' A '` 与 `'A'` 分别分组，strip仅用于判断是否全空白，不用于规范化键。前面JSON订单课接受仅由空白组成的非空名称，本课则拒绝；验证必须按当前合同判断。

坏行记录按遇到的顺序保存，每个坏行只记一次。异常边界放在单行预期解析与验证附近，避免把整个汇总程序的错误都当成数据坏行。空文本或全空白文本得到空groups与空invalid。

## 保留每组最后一次失败的位置

另扩展成检查报告，每组除了成功数与总数，还记录最后一次失败的原物理行号；从未失败用None。坏行继续进入独立invalid列表，不作为某组失败次数。

安排同组成功、失败、空行、坏JSON、再次失败的序列，再给另一组只有成功。核对最后失败位置指回原文本，total只计有效记录，未失败与第0行不能混用。新题增加分组状态与原始位置关联，需要独立设计。自行审查结果，不自动增加游戏成绩。
