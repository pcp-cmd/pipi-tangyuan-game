# 把账本变成 JSON

船上的程序保存着字典，岸上的程序却只能收到一段文字。把字典直接打印出来，看着像账本，并不意味着另一端能按约定恢复它。双方需要一种共同的文本格式，JSON正是这种用途。

本课要完成 `encode_ledger(ledger)` 和 `decode_ledger(payload)`。前者根据传入账本产生JSON字符串，后者根据收到的字符串恢复数据。它们不是先后绑定的一对暗号；解码函数必须能接收从未由你这次编码函数产生的另一份文本。

## 文字中的 true 与程序里的 True

先用普通Python观察列表的往返，暂不实现两个目标函数。

```python
import json

message = ["开门", True, None, 3]
wire = json.dumps(message, ensure_ascii=False)
print(wire)
received = json.loads(wire)
print(received[1] is True)
print(received[2] is None)
```

输出的第一行是 `["开门", true, null, 3]`，后两行均为True。JSON里的小写true和null分别恢复成Python的True和None。字符串与其中表示的数据，是两个不同层次。

`dumps` 把数据编码成字符串，`loads` 从字符串解码。这里名字末尾的s可以提醒你它处理字符串；与读写打开的文件对象的dump/load要区分。`ensure_ascii=False` 让中文直接显示，默认转成Unicode转义的JSON同样可以恢复中文，不能只凭文本外观判定数据不同。

## 不要靠记住上一份账本解码

初始账本是汤圆、80金币。把编码结果固定写成这份账本的文本，只能对付一次演示。把解码函数写成直接返回外面的 `ledger` 更隐蔽，它甚至能让这一份往返看似正确，但收到皮皮的新账本时仍交回旧内容。

真正的解码必须依赖payload。当前数据包括字符串键的字典、嵌套字典与列表、整数、布尔值和None，文字里可能有换行或引号。交给json模块处理转义，手工拼引号很容易把字段内容误当结构。

不要用 `str(ledger)` 替代JSON编码。它可能使用单引号、True和None，这些不是JSON对应写法。也不要用eval恢复收到的文字，解析数据不需要执行对方给的代码。

编码不应改动传入账本，解码也不应偷偷依赖共享全局状态。当前合同不要求序列化任意Python对象，也没有保证任意巨大或恶意文本都能安全处理。

## 给账本信封加版本

另设计一对函数，发送文本中的顶层对象包含 `version` 和 `data`。只接收版本1，遇到其他版本要明确拒绝，账本内容放在data中。解码时还要拒绝缺少version或data的信封。
