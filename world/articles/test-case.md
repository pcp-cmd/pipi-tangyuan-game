# 先证明，再出航

“运行没报错”不等于账算对了。若一个错误函数把除不尽的结果偷偷取整，拿8除2测试仍会得到4。好的检查要挑能让错误露出来的输入，而不是只挑一眼顺利的例子。

本课先完善 `safe_divide(a, b)`，除数0时返回 `None`，其他情况做通常除法。然后写实际执行的 `assert`，让它们能抓住“零除返回0”和“误用整除”两种错误版本。

## 把期望写成会失败的判断

`assert 条件` 在条件为真时继续，在条件为假时抛出 `AssertionError`。下面检查一段邮编文字的长度，可在普通Python运行。

```python
label = "A07"
assert len(label) == 3
assert label[0] == "A"
print("牌子检查通过")
```

输出“牌子检查通过”。它检查了具体性质，既没有自己给自己判真，也没有只打印一份结果让人猜。

这个反例故意失败。

```python
label = "A07"
assert len(label) == 2
```

看到 `AssertionError` 是这里期待的观察。若错误输入也一路打印“通过”，检查就没有起作用。正式提交的断言要符合正确实现，不能故意留下必失败断言。

## 哪些输入能区分两种错误

对零除情况，只判断结果为假不够。0和None在条件中都是假，但合同要求None。先说清“没有数值结果”和“数值恰好为0”的区别，再选择身份判断 `is None`。

对于通常除法，应选不能整除的正数或负数，让结果有小数部分。用6除3无法区分 `/` 与 `//`；用7除2则能。负数的整除向下取整，也不只是把小数点后抹掉。

你的断言必须调用自己的函数并在提交运行时执行。只把断言放进一个从未调用的测试函数，不会产生检查；捕获 `AssertionError` 后不再报告，也掩盖了失败。课堂会把函数临时替换成两种错误版本，检验你的断言是否真的反驳它们。

`assert` 适合开发检查，但Python启用优化模式时可以去掉断言。因此需要一直执行的用户输入校验不能只靠assert。本课运行与示例均以未开启优化的模式为准。

## 为一条错误消息设计反证

另写一个把空文本拒绝为 `ValueError`、非空文本原样返回的函数，并设计测试。拿“返回空字符串而不抛错”和“偷偷strip后再返回”两个错误候选验证测试。

选择包含两端空格但并非空串的输入，先写期望，解释它为何能区分“原样保留”和“清理空格”。捕获预期异常时要检查异常类型；若根本没有异常，也要让测试失败。

新题从比较返回数值扩展到异常合同和原文保留。保存正确版通过、两个错误版分别失败的原始输出，这只是自核证据，不是游戏对迁移题的自动判定。
