# 雾夜里的有限航程

灯塔今晚只剩六份电量，待做的查询依次耗费2、5、1份。皮皮可以先做第一项，剩4份；第二项需要5份，所以必须停下。不能跳过第二项去做第三项，因为这些任务的先后关系已经约定好了。

本课实现 `plan_calls(costs, budget)`。costs与budget都是非负整数。按原顺序选择能装入预算的前缀，遇到第一个超预算的成本就停止，返回 `[选中数量, 剩余预算]`。这里仅做计划，没有外部调用。

## 前缀是一段连续的开头

“选能负担的任务”可能有不同意思。本课是连续开头，不是找尽可能多的便宜任务，也不是挑最重要的任务。排序成本或跳过贵项都会改变原顺序与任务含义。

每次考虑下一项之前，先比较它的成本与当前剩余额度。足够才计入并扣减，不足就终止。若先扣掉再检查，可能留下负数，并把没有被选中的项也算进数量。

先观察一次独立的电量判断。

```python
remaining = 4
next_cost = 4
print(next_cost <= remaining)
remaining -= next_cost
print(remaining)
print(0 <= remaining)
```

输出是True、0、True。恰好够用可以执行，扣完后允许为0。剩余为0时，成本也为0的任务仍然可以选，所以不能简单地把循环条件写成“只要余额大于0”。

## 零成本也是一项任务

成本 `[0, 0, 1]`、预算0时，选中数量应为2，剩余仍为0。免费不等于没有发生一项工作。空costs则选中0项，预算完整保留。

对 `[2, 5, 1]` 与预算6，选择第一项后就停止，结果为 `[1, 4]`。如果你的程序返回选中2项，检查是否使用continue跳过了5。对 `[2, 4]` 与预算6，恰好全部选中，结果为 `[2, 0]`。

在纸上给每一项写“考虑之前的剩余、是否选中、考虑之后的剩余”。选中后的成本之和与剩余额度应合起来等于原预算。这个关系能发现重复扣除，但也要核对选中项确实是一段前缀。

## 计划预算与实际成本不同

本课的成本在开始前已知，且没有异常、超时与并发。真实工具可能估计耗费1份，实际用了2份；也可能超时后仍产生效果。因此计划上限不能代替执行中的取消、账单核对或持久回执。

前面的Agent循环把预算定义为决策次数，这里定义为成本总量。两个数字有不同单位，不能因为都叫budget就混用。先在接口里说清一份预算花在什么动作上，再决定什么时候减少。

## 同时受时间与金额限制

新任务的每项成本改为 `{minutes, coins}`，预算也分别提供时间与金币。仍按顺序取前缀，只有两份预算都够才接受；任意一份不足都停止。返回选中数量和两份剩余额度，不修改输入。

用一项免费但耗时、一项不耗时但收费、两份预算恰好耗尽和中途只超一种预算的例子手算。不要把分钟与金币相加成一个总成本，它们不是同一种量。

这项迁移改变了可接受条件与不变量，在自己的Python文件中人工核对。原单预算课堂通过不自动证明双预算计划正确，更不证明真实工具执行费用受控。
