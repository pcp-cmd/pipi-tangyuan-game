# 放进信封的便条

岛上的开船通知刚从八点改成九点。汤圆把新通知存好了，却仍拿旧便条去问“几点出发”。回答者只能看到这次交到手里的资料，不能因为电脑里另有一份新文件，就自动知道它的内容。

本课要把这条信息边界写成程序。实现 `ask_with_notes(model, question, notes)`，构造一个新字典，恰好包含 `question` 和 `evidence`。问题原样放入，资料是notes的新列表副本。只调用model一次，把它返回的原对象交回调用者，不修改notes。

## 保存和传入之间还有一步

先确认你会调用函数、创建字典和列表，以及用小测试观察输入输出。这里的model只是传进来的可调用函数，不需要网络或模型账户。

```python
saved = ["渡船八点开"]
visible = list(saved)
saved[0] = "渡船九点开"
print(saved)
print(visible)
```

输出先是 `['渡船九点开']`，再是 `['渡船八点开']`。`list(saved)` 在那一刻创建另一个外层列表，后来的元素替换不会倒流到先前副本。这段例子演示快照，不表示游戏要自动保存旧通知；任务收到哪一份notes，就必须把那一份交出去。

本次调用真正交给回答函数的数据叫上下文。它由传入的值组成，不由硬盘上“可能有”的资料组成。空notes就传空列表，不能偷偷补一段猜测或硬编码答案。旧资料也不能假装是新资料。程序负责准确传递，资料是否够用要由后面的任务另行判断。

## 函数也可以作为一个值

在 `helper = read_note` 中，helper保存的是可调用对象，没有执行读取。写 `helper()` 才发起调用。model参数也是如此。你应把构造好的字典交给它一次，而不是先调用一次查看结果，再调用第二次拿来返回。

结果可能是字符串，也可能是字典、None或别的对象。本课不要求解释或整理结果。若把原字典重新复制、把None换成空文字，都会改变“原样交回”的约定。

为什么资料列表要复制，结果却不复制？因为它们的所有权约定不同。输入notes由调用者持有，model拿到另一份外层列表后，即使调整列表顺序，也不应改变调用者的列表。返回值则明确要求保留原对象。这里notes的元素都是不可变字符串，复制外层就足够；如果元素将来换成可变字典，外层复制并不能隔离字典内部修改。

## 用看得见的调用证明传对了

准备一个假的model，让它记录收到的字典，再返回一个你事先创建的对象。分别传空资料、旧通知、新通知，检查收到的字段与顺序。让假的model清空收到的evidence，调用者的notes仍应保持。最后确认调用次数为1，返回值就是原对象。

这个检查验证的是信息流，没有测量真实语言模型是否理解通知。更完整的资料索引、权限和更新后复核，可以在[档案馆·可复查的研究](../integration/engineering-labs/evidence-research/learner/README.md)工程中用真实文件完成。领取工程、保存材料和作者示例通过都不会自动变成你的独立工程成绩。

## 两份资料不够时，保留缺口

新任务接收 `question` 和一份按来源名分组的字典，例如weather与timetable。调用者额外指定必须提供哪些来源。为回答函数构造两部分输入，一部分保留实际找到的资料，一部分列出缺少的来源；不能为缺失项编造文字，也不能因为缺少一项就丢掉其他已经找到的资料。

你自己定义这份新输入的字段名，先给“全部找到”“只找到一份”“全部缺失”和“原资料后来被修改”写预期。说明哪里需要新容器，哪里保留原文字，然后实现并用记录函数检查。

这项迁移改变了资料组织与缺失信息表达，由你在原生Python中人工核对。当前游戏判题仍只检查本课的一次调用合同，不给新题自动记分。
