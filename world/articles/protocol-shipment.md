# 不会漂移的运单：签字以后，重量还能变吗

皮皮把一张运单交给报价员，自己手里还留着原来的重量列表。报价员刚算完，皮皮又往列表里补了一件货。如果运单只是保存了这个列表的引用，那么运单“昨天签字时的内容”就变了。后续账目会对不上，而且没有人显式修改过运单字段。

这课建立在对象属性、列表与元组、浅复制之上。先确认你能解释：把列表赋给另一个名字并不会复制内容；元组本身不能增删元素，但元组中若装着可变对象，那些对象仍可能变化。我们的重量都是整数，因此转成元组能得到适合本题的稳定快照。

## frozen 阻止的是哪一种修改

`dataclass` 可以根据字段生成初始化、比较等常用方法；`frozen=True` 会阻止通常的字段赋值。它不会顺便递归冻结所有字段中的对象。下面故意展示这个边界，方便你识别“看起来冻结了”的错误方案。

```python
from dataclasses import dataclass, FrozenInstanceError

@dataclass(frozen=True)
class Notebook:
    pages: list

source = ["第一张"]
book = Notebook(source)
source.append("第二张")
print(book.pages)
try:
    book.pages = []
except FrozenInstanceError:
    print("字段不能重新赋值")

snapshot = tuple(source)
source.append("第三张")
print(snapshot)
```

先看到书中也出现了第二张纸，再看到字段赋值被拒绝，最后快照仍只有前两张。冻结属性与复制外部容器是两个动作，缺一个都不能得到这课需要的稳定运单。

## 把收到的数据变成自己的表示

本课的 `Shipment(identifier, weights)` 是冻结的数据类。编号必须是字符串，否则抛 `TypeError`；去掉首尾空白后不能是空串，否则抛 `ValueError`。规范化后的编号才是运单保存的编号。

重量来自有限序列，保存为元组快照，至少一项；每项必须是严格的正整数，布尔值不算。Python 中 `True` 会在一些数字运算里表现得像 `1`，所以只用宽松的整数判断会放进不该接受的货重。空序列、零、负数以及非整数重量都违反这课的重量要求，要抛 `ValueError`。

字段注解只是声明意图，不会自动做这些运行时检查。写了 `identifier: str`，Python 仍可能让构造函数收到数字。数据类提供的初始化之后，可以在 `__post_init__` 做验证和规范化；冻结实例的这个构建阶段若需要设置规范值，要理解 `object.__setattr__` 的作用。它用于完成内部构建，不是给日常调用者随意绕过冻结的借口。

请先画清三份东西：调用者的原始输入、验证期间的临时值、实例最终持有的值。最终表示一旦确定，外部列表继续增删，不应影响实例。两个规范化内容相同的实例应相等，而且能够用作字典键或集合成员。只有字段都适合哈希时，生成的哈希行为才有基础；“冻结”本身不能让任意列表突然可哈希。

例如，编号 `" A-7 "` 与 `"A-7"` 在规范化后应表示同一编号。反例则是直接把原字符串、原列表塞进字段：一个会让本应相同的编号不相等，另一个会让运单跟着外部列表漂移。不要为了方便把重量先全部 `int` 转换，那会把 `2.8`、`True` 等非法输入悄悄变成另一份货物数据。

这课防的是普通程序中的意外修改，不是抵抗恶意代码的安全边界。有限序列以外的输入行为也不要自行扩展成新的题目要求。
