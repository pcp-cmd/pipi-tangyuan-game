# 同一优先级的人，继续按原次序等待

救援单先处理早一天，再在同一天里让紧急者优先。同一天、紧急程度也相同时，报名先后不能被姓名的字母顺序覆盖。这次排序与集市排名课不同：名字是输出标识，不是平局裁决者。

你已学过多项排序键。这里的输入是字典列表，每条有id、day和urgent。键只应表达真正的业务优先级；稳定排序意味着键相等时仍按原输入顺序排列，正好承担本课的平局责任。

## 没有写进键的次序也可能被保留

在普通Python中，只按箱子的批次排序，观察同批箱子。`lambda row: row[1]` 创建一个接收row并返回其第1项的小函数，与排名课先定义 `order_key` 再传给key承担相同职责，只是写法更短。

```python
boxes = [("z", 2), ("a", 2), ("m", 1)]
ordered = sorted(boxes, key=lambda row: row[1])
print(ordered)
print(boxes)
```

输出 `[('m', 1), ('z', 2), ('a', 2)]`，然后是原列表。z与a的键都是2，原来的z在前这一关系保留。若把名字也放进键，就会使a排到z前面，稳定性救不回一个已经被新增条件打破的平局。

本课day升序优先。urgent是布尔值，而Python常规升序会把False排在True前，所以要把同日“True先”的要求转换成合适的第二项比较值。请自己设计这个键，并用一早一晚两天证明紧急只在同日参与比较。

## 不能让后一天的紧急者抢到前一天

day1的普通a、day2的紧急b、day1的紧急c，应依次是c、a、b。把urgent放在第一键，会让b越过a；给整个排序reverse，又会把日期方向也反转。两个优先级是有主次的，不是都叫“优先”就能任意交换。

同一天同urgent的z、a、m必须保持z、a、m，不按id排序。重复id也代表多条记录，输出要保留多次出现，不能先转成以id为键的字典。空输入给空列表。使用返回新列表的排序方式，避免把调用者的原救援单重排。

自核时不仅看最终名字，还暂时对照每条原始索引，确认相同键的索引递增。这样能直接证明稳定要求，而不是碰巧选择了本来就按名字排好的样例。

## 先分组展示，组内仍保留登记顺序

另设计按港口分组的救援看板。港口按名称排序，每组内部按day升序、同天urgent优先，同键保持输入顺序。输出是港口到完整记录列表的结构，不只是一条id名单。
