# 制作不可变坐标卡

地图上两张卡都写着横坐标4、纵坐标7，它们应表示同一个位置。若卡已经作为查询表的键，又被改成另一个位置，查找约定就会混乱。本课让坐标按字段比较，并拒绝普通属性改写。

你已知道实例保存属性，也知道int注解不会自动验值。dataclass可以根据字段声明生成初始化、显示与相等比较等重复代码。类前的 `@dataclass(...)` 是把这些规则应用到这个类上的装饰器；本课使用它，不要求先写自己的装饰器。

## 字段相同可以相等，冻结另有作用

下面用普通Python看一张单字段站名卡。它没有本课要求的坐标类型校验。

```python
from dataclasses import dataclass, FrozenInstanceError

@dataclass(frozen=True)
class StopCard:
    name: str

first = StopCard("北岸")
second = StopCard("北岸")
print(first == second)
print(hash(first) == hash(second))
try:
    first.name = "南岸"
except FrozenInstanceError:
    print("普通改写被拒绝")
```

输出True、True和“普通改写被拒绝”。`frozen=True` 让普通赋值无法改字段。相等且可哈希的对象需要给出相同哈希，才能作为字典键或集合成员使用；不同对象可以哈希碰撞，不能用“哈希相同”代替相等比较。

冻结不是深度安全屏障。若字段中保存列表，列表内容仍可能变化，也未必能哈希。本课用严格整数坐标，避免把可变容器放进坐标值里。

## 创建卡片时就拒绝错误类型

目标类名是 `Coordinate`，字段顺序为 `x: int`、`y: int`，使用frozen dataclass。它们可以是负整数，也可以很大；布尔值、浮点数、文字和None都要抛TypeError。

注解不会自动做到这一点。dataclass生成的初始化完成字段设置后，会调用你提供的 `__post_init__(self)`，这是检查字段的合适位置。函数名两侧是两个下划线。这里只需要检查，不需要改写冻结字段。

反例 `Coordinate(True, 1)` 看起来能参与数值运算，却违反严格int。`Coordinate(1.0, 2)` 与整数坐标比较可能数值相等，也仍应拒绝。不要为了让它们通过而偷偷转换类型。

创建两张相同坐标卡，比较相等与哈希；再创建只改一个字段的卡确认不相等。最后尝试普通赋值，确认被拒绝。不要把“自己没有去改”当成冻结已经生效。

## 两端组成一张航线卡

另设计冻结的航线数据类，保存起点与终点两张坐标卡。约定起终点有顺序，因此A到B与B到A是不同航线。输入必须为坐标卡，不接受列表或两元素元组。

先决定如何验证字段类型，再预测两张相同航线卡在集合中是否合并。测试反向航线、同起终点的零长度航线，以及错误容器输入。

这次从简单字段扩展到两个值对象的组合，新增方向与嵌套类型责任。自核构造拒绝、相等、哈希与冻结，不把普通属性保护说成能抵御任意绕过的安全机制。
