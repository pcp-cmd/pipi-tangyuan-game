# 工具门口的检查

汤圆收到“读取时钟”的建议，码头登记表里确实有只读时钟。另一个建议要求“取消所有订单”，登记表却没有这种能力。纸上的建议不能自行给程序安装新能力，只有宿主交来的登记表决定可以调用什么。

本课实现 `dispatch(decision, tools)`。tools把名称对应到无参数只读函数。先检查建议结构与kind，只有合法的tool建议才继续查登记表。坏结构或final返回 `{"status": "bad_output"}`；名称没有登记返回 `{"status": "denied"}`。这两条路径必须零工具调用。

## 选中函数不等于执行函数

先读这个只演示调用时刻的小例。运行前预测两次打印的列表分别有什么。

```python
events = []
def read_flag():
    events.append("读取")
    return False

tools = {"flag": read_flag}
selected = tools["flag"]
print(events)
value = selected()
print(events, value)
```

第一行是 `[]`，第二行是 `['读取'] False`。登记和选择都没有读取，括号调用才使events变化。如果写成 `{"flag": read_flag()}`，登记表构造时就已经执行，存下的也会是结果而不是函数。

这说明拒绝检查必须位于真实调用之前。先调工具，之后再返回denied，只是把事实藏了起来，并没有阻止操作。验收会记录调用次数，不能靠最终文字掩盖提前执行。

## 结果为假仍然是成功结果

选中已登记工具后只调用一次，返回 `{"status": "tool_result", "result": 原结果}`。None、False和0都可以是合法结果。不要写成“结果为空就tool_error”，也不要把结果变成字符串。

若工具返回一个字典，result字段要指向同一个字典对象。本课只负责传递，不负责复制或重写业务数据。输入decision和tools登记表也不能被修改，删除工具、pop字段或替换原结果都超出了分发器职责。

## 哪种错误可以转成状态

读取工具可能发生OSError，本课约定把这一类错误转为单字段 `{"status": "tool_error"}`。其他异常必须原样向外传播，包括它原来的对象身份。

这个区别让调用者能区分预期的读取失败与程序写错。把所有Exception都吞掉，会把ValueError或RuntimeError变成同一种普通状态，真正的缺陷就失去线索。try范围也应贴着工具调用，不能把整个函数里无关的错误都当成工具错误。

当前工具由练习环境提供，不会因为文章提到OSError就开放本机任意文件。真实CLI、回环HTTP、stdio进程与错误回收在[工坊的工具桥](../integration/engineering-labs/tool-bridge/learner/README.md)工程中另验；该工程的公开自测与可信审核仍分开记录。

## 给工具加一个只读参数

新任务的建议多一个args字典，工具函数必须接收这份参数。只有名称已登记、参数通过该工具自己的检查后才能调用。不要直接把所有字段展开成关键字参数，也不要替调用者补造文件路径。

你自己定义两个工具，一个接收站点名，一个接收非负计数。设计错误名称、错误参数类型、缺字段、合法0和工具自身抛错的案例。用调用列表证明拒绝时没有执行，并区分参数无效与执行中的业务异常。

这项迁移增加了每个工具的输入合同，不能只在本课函数后补一对括号。它在原生Python中人工核对，不自动写入游戏成绩，也不授予真实外部操作权限。
