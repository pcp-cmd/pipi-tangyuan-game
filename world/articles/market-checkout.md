# 一张订单要么全成，要么不动旧库存

鱼够了，水不够。若先扣掉鱼再发现缺水，订单虽然返回失败，仓库却少了鱼。失败后的库存不应取决于订单里哪件商品写在前面。

本课输入是两份字典：库存和订单，数量都是非负整数。成功时交回扣除后的新库存；任一商品不足时返回 `None`。`None` 是这道题的失败标记，空字典则可能是一份成功的空库存，不能用 `if result` 混为一谈。

## 先把改变放在自己拥有的草稿里

普通Python中可以观察草稿怎样保护原件。这里仅演示一项候选扣减，不是完整结算函数。

```python
stock = {"lamp": 4, "rope": 2}
draft = stock.copy()
draft["lamp"] -= 3
print(stock)
print(draft)
print(draft is stock)
```

输出依次是 `{'lamp': 4, 'rope': 2}`、`{'lamp': 1, 'rope': 2}`、`False`。草稿有独立外层，值都是整数，扣减让草稿里的键改为指向新整数，不会修改旧字典的条目。若值是列表，就不能凭这个例子推断浅复制也足够。

完整任务可以先确认所有需求再生成结果，也可以在自己的草稿上试算，失败时放弃草稿。两条路都要守住同一责任：原库存始终不变，成功才把完整新结果交出去。请自行组织遍历、检查与返回，不要把返回语句放在只检查完第一件商品的位置。

## 缺失、零和失败分别是什么

缺少某键表示现货按零处理。正数量订单若找不到该商品就不足；订单数量为零则没有缺口。成功的结果保留原有库存键，包括扣至零的项。题目的参考规则还允许订单带来一个原库存没有的零数量键，处理时把它作为零库存记录保留，而不是因键缺失就一律拒绝。

试想库存鱼5，订单鱼2、水1。函数必须返回None，原库存仍是鱼5，不能留下鱼3。把订单次序反过来，失败含义也应一样。再试鱼2买鱼2，结果应保留鱼0；把零键删掉会丢失“已登记但售罄”的信息。空订单也必须得到新库存对象，不能直接把原件交还给调用者改动。

这是一段内存计算的“全有或全无”规则，不是数据库交易或网络支付保证。若两个调用者同时拿旧库存结算，还需要另外的并发规则，本课没有模拟这一点。

## 让订单变成可审查的提案

另写一个预订工具，成功返回 `{'ok': True, 'after': 新库存, 'changes': 扣减明细}`，失败返回 `{'ok': False, 'missing': 缺口表}`。失败时要列出所有缺口，不能遇到第一件不足就停止报告。

准备一张两件都不足、另一件刚好够的订单，核对缺口只报不足项且数量正确；再检查成功明细与库存差值逐项一致，两种路径都不改输入。输出协议与失败收集责任已经改变，当前返回None的解法不能直接照搬。保存预测和运行结果自行验收，这道提案题不自动登记成绩。
