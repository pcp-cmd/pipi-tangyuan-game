# 为商店建立模型

鱼饼铺今天有5份库存。卖出2份后只剩3份，再来一笔4份订单必须拒绝，而且拒绝不能把库存减成负数。库存与影响库存的操作需要放在同一个对象里，调用者才知道自己在操作哪间店。

你已会函数、条件与字典。类是描述一类对象的数据和操作的方式，由类创建的具体对象叫实例。`self` 指向正在被操作的那一个实例，不是所有商店共用的库存名字。

## 先让两盏灯各记自己的状态

普通Python例子用灯说明实例属性与方法，不实现销售。

```python
class Lamp:
    def __init__(self, label):
        self.label = label
        self.on = False

    def light(self):
        self.on = True

left = Lamp("码头")
right = Lamp("工坊")
left.light()
print(left.on, right.on)
```

输出 `True False`。创建每盏灯时，`__init__` 给这一盏灯保存初始属性。调用 `left.light()` 时，Python把left作为self交给方法，所以right不被改动。

把会变化的业务状态错误地存在所有实例共用的地方，两个对象就可能互相影响。本课起始代码已把库存放在 `self.stock`，保留这个所有权，让每间店维护自己的库存。

## 先判断能不能改，再改一次

`Shop.sell(count)` 的输入数量与初始库存都是整数。count必须为正，而且库存足够，才减少stock并返回真正的True。数量为0、负数或超库存时，返回False并保留原库存。

负数尤其值得先测。如果不检查正数，卖负2份再执行减法，库存反而会增加。先扣库存再发现不足，则拒绝也留下副作用。把“是否允许”与“成功后的修改”分成先后两步，可以避免这些错误。

库存刚好等于count时应允许，之后库存为0。下一笔正数订单再被拒绝。还要连续调用同一实例，不能每次sell都从构造时的初始库存重新开始。

返回True不代表扣款、保存文件或其他进程已收到通知。这课是单个内存对象的顺序调用，不能把它宣称为并发交易或持久库存系统。

## 先整批验货，再决定出售

另为商店设计 `sell_batch(counts)`。输入一批正整数数量，只有全部合法且总量不超过当前库存时，才一次性扣除总量并返回True；任一项非法或总量不足，库存保持原样并返回False。空批次按你明确写下的规则处理。

用库存5和订单 `[2, 4]` 检查整批拒绝，不能先卖2再发现后面不足。再测 `[2, 3]`、含0、含负数和连续两批。

新题增加整批一致性，不能逐项调用sell后就把失败以前的变化留着。自核每次前后库存与返回值，保留两实例互不影响的证据；原单笔销售通过不自动证明整批规则。
