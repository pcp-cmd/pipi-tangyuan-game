# 给航海助手一份成绩证据

助手做了十次查询，其中八次成功；又试了两次修改，两次都失败。如果只展示八条成功记录，看起来像每次都做好了。若只报一个总体比例，又会遮住修改任务完全不会做的问题。

本课实现 `score_groups(rows)`。每条记录有group和布尔passed。结果按组保存通过数passed与总数total，失败样本也进入分母。输入为空返回空字典，不补出从未出现的组。

## 总数为什么要先于成绩保留

一个组有三次尝试，两次通过，应该保留2与3。只有分子2，别人不知道它来自两次尝试还是两百次尝试。只把通过记录拿来统计，总数也会变成2，失败就消失了。

```python
outcomes = [True, False, True]
passed = 0
for result in outcomes:
    if result:
        passed += 1
print(passed, len(outcomes))
```

输出是 `2 3`。这个小例只有一组，完整任务还要为每个实际组名维护独立的计数。不要让所有组共用同一个可变字典，否则给read加一时write也可能跟着变化。

每读到一条记录，总数增加一次；它通过时，通过数也增加一次。先把这两个条件分别写清楚，再考虑怎样保存。输入已经保证passed是bool，本课统计层不负责辨认自报成绩是否可信。

## 同一个组不一定挨在一起

真实测试可能交错执行read、write、read。第二条read到来时，应接着原read计数，而不是重建一份清零。同一组的两条成功记录是两次样本，不能因为内容相同就去重。

组名来自输入。除了read与write，还可能有search或中文名称。不要提前硬编码只有两个桶，也不要在只出现read时补一个total为0的write。全失败的新组仍应存在，passed为0，total保留全部尝试。

最终每个组都应满足 `0 <= passed <= total`。这条关系可以帮助发现重复加分或漏记总数，但不能单独证明分类正确。把样本放错组，数字仍可能符合这个关系，所以还要用交错组的手算结果核对。

## 统计正确不表示评估有效

这些记录如果都来自训练时见过的题，正确统计也不能证明陌生任务会做。passed由谁判、失败是否被删、帮助来源、任务规模是否相同，都影响解释。

工具桥工程会用真实调用与文件效果独立检查结果，并保留全部试验分母与危险效果的否决。课堂的“海神大使”依据保存的99项独立课堂记录派生，仍不代表工程构建、排错、迁移和真人答辩已获可信审核。

## 增加“没有测到”，别把它当失败或成功

新记录有group与status，status可以是passed、failed或skipped。结果分别保留三类数量，并额外报告实际执行数。事先约定通过率的分母只包含实际执行的样本，同时必须让跳过数可见。

为只有skipped的组决定如何表达通过率，不能除以0，也不能写成100%。再测试交错组、全失败、一次成功一次跳过与空输入。解释为什么“跳过未计入通过率分母”必须同时展示跳过数量，才不致隐藏覆盖不足。

这项迁移由你人工核对，没有自动写入课程成绩。先保留原始逐条记录，再产生汇总，确保别人可以从原记录重新算出同一份结果。
