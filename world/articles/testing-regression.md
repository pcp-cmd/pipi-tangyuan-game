# 修过的解析错误，要留下能再抓住它的测试

数量0被当成“没有数量”，100被多放进上限，坏文本直接抛错，带正号的合法整数又被isdigit拦下。这四种故障不是多测几个随机数字就一定能看见；每一种都需要一个能区分正确与错误行为的输入。

本课写 `check_quantity(candidate)`。candidate只接收字符串，正确行为是按整数文本规则转换，值在0至99时返回整数，否则返回None。你的测试不能读候选源码，应通过调用观察结果；对正确实现不抛错，对四种指定错法形成AssertionError。

## 结果错了和意外抛错，都应成为测试失败

下面的普通Python小测试检查一个字符串规范化器是否接受空字符串，演示将意外异常报告成断言失败。沿用测试课的小函数写法，`lambda text: text.strip()` 接收text并返回清理首尾空白后的字符串。

```python
def check_empty_text(candidate):
    try:
        actual = candidate("")
    except Exception as error:
        raise AssertionError("空文本不该抛错") from error
    assert actual == ""

check_empty_text(lambda text: text.strip())
try:
    check_empty_text(lambda text: int(text))
except AssertionError:
    print("测试拒绝了错误行为")
```

输出 `测试拒绝了错误行为`。正确小替身正常结束，错误小替身的ValueError被测试解释为AssertionError。这里捕获Exception来报告候选行为失败，不把KeyboardInterrupt等进程控制异常当作普通测试数据。

数量题里，坏文本按合同应返回None。若候选直接int并抛ValueError，你的测试要把它记录为测试不通过，而不能让这种异常冒充规定的断言失败或被当作成功忽略。对于本应成功的输入也要确认结果，不是“没有异常就算通过”。

## 输入的两层边界都要覆盖

先检验转换语法，再检验数值范围。0是合法下界，99是合法上界，100在外；非法文本无法转换，结果None。Python的int可以接受合法首尾空白和ASCII正号，因此仅用isdigit预筛会拒绝一些合法字符串。测试里要真正出现这样的输入，而不是只在说明里提到。

这与你已经写过的数量解析规则一致：不要把Unicode相似正负号规范化成ASCII符号，也不要先删除任意控制分隔符。当前回归任务只规定四类必须拦下的错法，你可以增加合同内案例，但新增期望也要与Python整数转换语义一致。

选择期望时区分None与0。`assert not actual` 会让它们同时通过，正好掩盖拒绝0的故障。也不要自己调用int得到一个值后只检查自己，必须比较candidate的真实返回。先把测试对照两份行为正确但写法不同的实现运行，避免只接受某种代码样式。
