# 只读一次的货流：看过一遍，就已经过去了

皮皮接到一条装卸记录，每次从传送带上读出一个整数。正数代表入库，负数代表出库，零也是一条正常记录。记录不是随时能回翻的账本：已经读过去的项目，不保证还能读第二遍。

这一课需要循环、整数加法和函数返回值；如果你见过带 `yield` 的函数，也已经遇到过这类按次提供数据的对象。先把两个词分开：可迭代对象能提供迭代器；迭代器保存当前进度，`next` 让它前进一步，耗尽时用 `StopIteration` 表示结束。列表可以多次创建新的迭代器，而已经取得的同一个迭代器通常不会自动回到开头。

## 一次观察也会改变位置

```python
stream = iter([3, 0, -2])
print(next(stream))
print(list(stream))
print(list(stream))

numbers = [3, 0, -2]
print(list(iter(numbers)))
print(list(iter(numbers)))
```

前面三次输出为 `3`、`[0, -2]`、`[]`。第一次 `next` 已经消费了 3；第一次 `list` 消费剩下的内容；再次使用同一个流就没有数据了。后两行都输出完整列表，因为每次从列表创建了新迭代器。

这解释了一个常见调试陷阱：为了“先看一下输入”，在计算前打印 `list(stream)`，真正计算时却得到空数据。日志观察本身消耗了流。另一个错误是先遍历计数，再遍历求和：对列表测试没问题，换成一次性迭代器就失效。

## 累积量跟着每条记录更新

本课要求 `sum_stream(stream)` 计算全部整数之和，流可能只能遍历一次。总和在处理任何记录之前应为加法的起点 `0`；每取得一条，就把它的贡献计入当前总和。这样无需预先知道长度，也不用把整个输入复制成列表。

“没有更多记录”由迭代协议决定，不由数据的真假决定。若用读到 `0` 就停止的逻辑，`[3, 0, -2]` 会被错误算成 3；正确总和是 1。负数不是坏输入，它表示减少。空流的总和为 0，也不需要为了找第一项而报错。

这里可以用一个循环不变量检查自己：每次循环开始前，累积量等于已经处理的那部分记录之和。下一项加入后，这个说法继续成立；流结束时，已处理部分就是全部输入。这样的解释比“循环加起来就行”更能帮助你迁移到计数、求最大值或计算均值。

这份合同没有说输入可以无限不结束，也没有规定资源关闭方法。对真正无限的流，求“全部之和”不会返回；对文件或网络源，还需要额外决定谁负责关闭。当前先解决一次性、有限整数流的计算，不在这里隐式接管未知资源。

测试不要只给列表。用全新 `iter(...)` 分别构造正数、含零、负数和空输入；每个测试创建自己的流，避免前一个断言先把它耗尽。再设计一个只能推进、没有 `len` 的对象，确认实现没把“能迭代”误当成“能取长度”。

## 独立任务：一遍算出平均值和样本数

给一条只可遍历一次的有限温度流，返回 `(样本数, 平均值)`。空流返回 `(0, None)`；温度允许零和负数，平均值保留小数，不做整数截断。输入结束前不要保存全部温度。

先写出你需要保留的最少状态，再用 `[0, -2, 3]`、单个值和空流做测试。补一个会记录每次取值的迭代器，证明只消费一遍。最后解释为什么不能遇到零就停止，以及为什么空流要单独处理除法。这次新增了两个关联状态和空输入分支，需要自行核对；原课程的求和检查不会替它验收。
