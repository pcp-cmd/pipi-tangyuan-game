# 读懂JSON，还没读懂订单

漂流瓶里可能装的是一份订单，也可能是 `[]`，甚至是一段坏文本。JSON解析器能回答“这是合法JSON吗”，不能替货栈回答“它是不是我们接受的订单”。这两层检查必须分开。

本课 `decode_order(payload)` 接收JSON文本，成功返回解码的字典，失败返回None。字典必须恰有item和qty两个键；item是非空字符串，qty是严格整数、不是布尔且大于0。这里“非空”只排除长度为0的字符串，空格或制表符组成的非空名字仍合法，不能沿用CSV课程的非空白规则。

## 类型是在解码时确定的

下面用普通Python观察JSON里的三种写法。

```python
import json

values = json.loads('[2, 2.0, true]')
for value in values:
    print(type(value).__name__, isinstance(value, int))
print(json.loads('"  "') == "  ")
```

输出依次是 `int True`、`float False`、`bool True`，最后是True。Python中bool是int的子类，因此 `isinstance(True, int)` 不能排除布尔。若任务要求严格整数，要检查实际类型，而不能只看它是否能参与整数运算。

`2.0` 与 `2e0` 即使数学值为2，解码后仍是float，本课必须拒绝。把qty再交给int，会把不合规输入偷偷改成合法数据；把True转成1也同样破坏验证目的。验证检查原值是否符合规则，不是想办法凑成想要的值。

## 每一步都给下一步建立条件

先捕获预期的JSON解码错误。解码成功后，先确认是字典，再比较键集合是否恰为两项；之后才读字段并检查类型、非空与正数。若还没确认字典就直接取item，列表输入会让错误跑到不该出现的位置。

名称必须按解码原文返回。`" fish "` 的空格不删除，`" "` 也不拒绝。JSON引号中的转义会由解码器还原，程序不应再手工删反斜杠或压缩内部空白。额外的x字段不能忽略，因为本课约定只有两键；缺qty也不能默认1。

请用一个坏文本、一个合法数组、一个布尔数量、一个零数量和一个全空白非空名称分开定位。所有失败都返回None，但原因各不相同。不要只在最外层用裸except把拼错变量名等程序错误也吞成“坏订单”，那会使排错失去线索。

## 把失败原因也交给收货员

另做批量订单验证，输入是多段JSON文本，按原顺序返回每项的成功数据或失败代码。区分语法错误、顶层类型错误、字段集合错误和字段值错误；一项失败不阻止后面的项目。

自己确定错误优先级，并让一个输入同时缺字段且含错误类型，检查始终报告同一优先原因。保留名称原文、禁止布尔数量，并核对输出项数与输入一致。新题增加可诊断失败与批次隔离，不可只把当前None装进列表。人工核对不自动新增游戏成绩。
