# 亮着的信号，不是一箱货

灯塔亮起，表示现在可以取件。两名守候者都能看到灯光，却不能从“一次亮灯”推断仓里正好有两份包裹。另一盏灯写着“本次结束”，也可能是取件失败后亮起。信号帮助协调时机，结果还得从实际操作取得。

先完成等待回执的接力课，能分清协程、等待与结果。这里再用到 `try/finally`：已经进入的范围，无论正常返回、抛错或收到一次取消，都可以在退出时执行共同动作；如果协程还没开始就被取消，函数体内的 `finally` 也没有凭空进入过。

## Event 保存的是现在的状态

`asyncio.Event` 初始没有设置。`set()` 是普通同步调用，把标志设为真并唤醒已经等待的任务；`wait()` 是需要 `await` 的操作。标志已真时，后来等待的人也可以通过。`clear()` 把状态复位，未来的等待重新受阻，但不会储存“历史上亮过几次”。

下面让两个人确实都到达等待处，再亮灯并立即复位。原生 Python 3.12 可以独立运行；例子的入口 `asyncio.run` 不应复制进游戏函数内部。

```python
import asyncio

async def main():
    ready = asyncio.Event()
    entered = [asyncio.Event(), asyncio.Event()]

    async def watch(name, arrived):
        arrived.set()
        await ready.wait()
        return name

    first = asyncio.create_task(watch("皮皮", entered[0]))
    second = asyncio.create_task(watch("汤圆", entered[1]))
    await entered[0].wait()
    await entered[1].wait()
    ready.set()
    ready.clear()
    print(await first, await second)
    print(ready.is_set())

asyncio.run(main())
```

输出“皮皮 汤圆”和 `False`。两个已经被唤醒的等待都能通过，即使读取标志时它已复位。若有人在这之后才开始等，就要等下一次设置。这个顺序靠“已经到达”的事件建立，没有拿睡眠时长猜测调度。

因此，Event 不是一次交给一人的货物，也不是计数器。连续 `set()` 两次不会积累两张取货票；一个等待者自行 `clear()`，也不能把广播可靠地变成队列。需要一件一取的数据交接，应另学 `asyncio.Queue`，先设计数据所有权。

## 本次结束以后再亮 finished

本课 `receive_when_ready(ready, finished, take)` 使用调用者借来的两个不同 Event。实际开始后调用并等待一次 `ready.wait()`，通过后才调用并等待一次 `take()`，返回其同一结果对象。`take` 可以给出协程、Future 或自定义可等待对象，不能只接受其中一种。

本函数不清理任何一个信号，也不擅自设置 `ready`。信号复位归调用者管理；本轮中调用者不重复复用或重置 `finished`。多个等待者可以共享 `ready`，却各有自己的 `finished`，避免一个人的完成被误当成所有人完成。

从实际进入等待范围起，无论正常、普通异常还是一次取消，最后都要设置 `finished` 一次。若等 `ready` 时取消，`take` 不运行；若 `take` 已经开始，必须等它结束，包括取消路径上的异步 `finally`，再设置完成信号。`finished` 为真只说明范围结束，业务成功与否应看返回值或异常，不能因为灯亮了就把错误改成成功。

具体反例是在 `take()` 一启动就设置 `finished`。当它仍在等网络回执，界面已经认为结束；若后来失败，也没有地方报告。另一个反例是函数内部等待一个只能由它自己在后面设置的信号：无人能推进到设置点，形成死锁。每个信号都要写清“谁负责 set、谁负责 await”。

这课使用同一事件循环中的内存信号，不提供跨线程同步保证，也没有承诺在重复取消、硬终止执行环境后仍完成收尾。题设中正常的 `Event.set()` 不抛错，不需要为异样实现另添错误优先规则。

## 独立任务：两份报告都结束后再汇总

让两名独立报告员共享一个开始信号，各自拥有结束信号。每人取得自己的报告结果；其中一人失败，另一人仍继续。汇总者等两人的结束信号都到达后，再读取各自的成功或失败记录，输出保留人员身份的汇总。结束灯本身不能编码成功。

先设计每名报告员的结果记录，再分别测试“双成功”“一人立即失败、另一人仍等待”“其中一人一次取消”。用闸门证明汇总没有在第二人结束前出现，并解释为什么不能让两人共用同一个 finished。新增多参与者与失败汇总，需要你自己运行和人工审查；本课不会自动替这项迁移记分。
