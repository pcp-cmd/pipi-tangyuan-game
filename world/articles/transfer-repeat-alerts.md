# 告警的顺序，由第二次到达决定

信号a先到，信号b后到，但b在a之前重复。告警应先报b，再报a，因为我们报告的是“刚刚发现重复”的时刻，不是名字首次进入记录的时刻。

这是从去重与收据累计迁移来的独立任务。`repeat_alerts(ids)` 输入字符串列表，当某ID第二次出现时加入告警列表，第三次及以后不再重复告警。空字符串也是合法ID，不能按真假跳过；输入保持原值。

## 次数如何跨过一个门槛

下面在普通Python中只追踪一种信号的计数，没有实现整份告警函数。

```python
count = 0
for signal in ["bell", "bell", "bell"]:
    before = count
    count += 1
    print(before, count, count == 2)
```

输出 `0 1 False`、`1 2 True`、`2 3 False`。关键不是“现在是不是重复”，而是“这一次是否刚到第二次”。若条件写为次数大于等于2，第三次仍会再次告警。

多种ID需要分别保留状态。可以用计数表，也可以用“见过”与“已告警”两类记录，但请自己解释每个容器回答哪个问题。输出列表只在触发时追加，便自然记录触发先后；之后再按ID排序会改变题意。

## 用反转次序拆穿看似正确的办法

对a、b、b、a、b，第二次b发生在索引2，第二次a在索引3，因此结果b、a。若先统计最终次数，再按第一次出现顺序筛选，会得到a、b；数字都算对了，时间顺序仍错。

没有重复与空输入都应返回空列表。x、y、z、z、y、x应按z、y、x告警，这比a、a、b、b更能区分两种顺序。把同一个ID连发许多次，结果仍只出现一次。请同时保留空ID和中文ID样例，防止把字符串内容当额外筛选条件。

做自核时给每条事件写“旧次数、新次数、是否追加”，再核对告警列表的增长。读取完整输入统计再回头按第二次位置排序也可能得到正确结果，但你需要保存那些位置；单独一个最终Counter已经失去了触发时刻。

## 每隔三次重复一次告警

另做心跳监控：某ID第3、6、9次到达时分别告警，输出 `[ID,本次累计次数,原事件索引]`。所有ID共享输入事件流，但计数分别维护，不能把整条流的每第三项当触发。
