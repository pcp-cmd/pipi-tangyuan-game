# 注解不会替你验货

仓库表上写着“数量必须为整数”，不代表送来的每份数据已经检验。函数参数后的 `: int` 也是一种说明，不会自动挡住字符串、布尔值或负数。本课把接口说明与实际校验分开负责。

入口必须保留 `scale(amount: int, factor: int = 2) -> int`。冒号后的int说明参数预期类型，箭头后的int说明返回值预期类型。`factor=2` 是默认值，调用时省略它才会使用2。

## 先看说明没有阻止什么

普通Python中运行这个有注解、却没有校验的邻近例子。

```python
def echo_twice(value: int) -> int:
    return value * 2

print(echo_twice("ha"))
print(isinstance(True, int))
print(type(True) is int)
```

输出 `haha`、`True`、`False`。字符串也支持乘整数，运行时不会因为注解自动拒绝它。布尔类型是int的子类，所以宽泛的 `isinstance(..., int)` 包含True；严格检查实际类型是否恰好为int，则排除它。

这不是说注解没用。编辑器和类型检查工具可以据此指出不一致，读代码的人也能知道约定；但如果接口承诺运行时拒绝坏值，函数体仍要执行相应判断。

## 类型错误与数值错误分两步

本课只接受严格整数amount和factor，bool也拒绝。类型不合格要抛 `TypeError`。两者类型合格后，再检查数值是否为负；负整数要抛 `ValueError`。0合法，两个合法非负整数才计算乘积。

`raise TypeError("说明")` 会主动抛出类型错误；ValueError同理。不要把字符串“3”自动转成3，这样虽然能算，却取消了“严格整数输入”的约定。也不要返回一段错误文字，调用者约定收到的是异常。

具体反例包括 `amount=True`、factor为2.0、amount为负1、factor为0。前两种是类型问题，负1是值域问题，0却是合法整数。检查顺序应避免对陌生类型先做大小比较，导致异常类型由偶然运算决定。

保留原参数名、两个int注解、返回int注解和默认值2。这里的注解要求是实际int对象，不需要添加延迟注解的future导入。课堂既检查行为，也检查这个具体函数签名。

## 一箱数据里，哪几项不合格

另设计批量入口，接收若干待检查数量及一个严格整数上限。先验证上限，再逐项给出 `(位置, 合法与否, 原因)`，但不自动修正任何值。数量必须严格整数且在0到上限之间；布尔值、文字、负数与超限要能区分原因。

用 `[0, True, "2", -1, 9]` 和上限5预测五条记录。非法上限要整次拒绝，单项错误则保留其他项的结果。

这是从“失败就抛错的单次运算”变为“保留逐项错误报告”的责任变化。保存各类反例与位置核对，不把本课通过当成批量接口已验收。
