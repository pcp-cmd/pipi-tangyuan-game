# 可调节的打折器

皮皮每天给邻居打八折，汤圆每周给老客打五折。若每次收银都重新传百分比，容易拿错配置。更方便的接口是先建立各自的收银规则，之后只交商品价格。

本课实现 `make_discount(percent)`，返回一个可调用函数。之后调用这个函数并传入price，得到 `price * (1 - percent / 100)`。percent是0至100的有限整数或浮点数，price是非负有限整数或浮点数，允许零与小数。

## 返回函数，之后才交业务数据

先回想函数参数、返回值与局部名字。函数本身也是一个值，可以保存和返回。下面用尺子的起点演示两次创建各自的配置。

```python
def make_marker(origin):
    def locate(distance):
        return origin + distance
    return locate

pier = make_marker(10)
hill = make_marker(30)
print(pier(2), hill(2), pier(5))
```

输出为 `12 32 15`。调用make_marker时确定origin；之后调用pier或hill时才提供distance。外层结束后，返回的函数仍能访问它所需的外层绑定，这种函数与外层绑定的组合叫闭包。

`return locate` 返回函数本身，`return locate(...)` 则是在外层立即执行它，返回执行结果。两者决定了调用者之后还拿不拿得到可调用的规则。

## 每次创建都保留自己的配置

pier和hill来自两次外层调用，各有自己的origin。创建hill没有覆盖pier。若把配置写进同一个全局变量，后建立的规则就可能使旧规则也改变，这与题目要求不同。

折扣题同样要保留各自percent。创建20%、50%和0%三种折扣后，交错调用旧函数，确认新配置没有覆盖旧配置。只创建一个函数、只调用一次，很难发现共享全局状态造成的问题。

闭包保存的是可访问的绑定，不是把看到的一切自动冻结。循环中用同一个不断变化的变量创建多个函数，可能让它们之后都读到最后的值。当前题每次调用make_discount都有独立参数，因此不需要引入那种共享循环变量。

## 金额别在中途被截成整数

本课要求按公式计算，25%的折扣作用于7，结果为5.25。若使用整除或在最后无条件转int，小数部分就丢了。100%折扣与零价格也合法，结果为0，不能把0误当成配置缺失或错误。

这里用普通Python数值展示函数组合，没有要求模拟真实支付。现实金额的舍入、最小货币单位与退款规则应由业务另定，不能把本课的浮点公式直接当作财务系统。

## 配置一次，按不同单位读数

新任务建立一个温度转换器。创建时提供倍率和偏移，之后每次调用接收一个读数，按规定的顺序换算。要求两个转换器交错使用互不影响，并允许输出0或负数。

先用“先乘再加”和“先加再乘”各算一个例子，说明为什么顺序必须写进合同。再增加一个可选的允许范围，决定范围判断针对原始读数还是换算后结果，并把你的选择写清楚。

这个迁移题增加了两项配置及范围含义，需要你重新组织接口。它在自己的Python文件中人工核对，不会自动写入当前课程成绩。
