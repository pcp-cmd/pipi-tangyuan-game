# 先看清请求的形状

信封里有时是最终答复，有时是“去查一个工具”的建议。也可能只塞进来一个数字、空值或拼错字段的字典。程序在读字段之前，要先确认手里拿到的是哪种东西。

本课实现 `valid_decision(value)`，始终返回布尔值。value必须是字典，kind只能是final或tool。final要求text是字符串，空字符串也合法。tool要求name是非空字符串，只有空字符串不合法。额外字段不影响这个判断，函数不修改输入。

## 先确认容器，再碰字段

上一课用字典传递问题和证据。现在收到的是别人给出的值，不能直接假定它同样守约。`None.get(...)` 会报错，因此容器检查必须先于取字段。

```python
parcel = {"label": "", "weight": 2}
print(isinstance(parcel, dict))
print(parcel.get("label"))
print(parcel.get("missing") is None)
print(isinstance(parcel["label"], str))
```

输出是True、一行空行、True、True。空字符串依然是字符串，字段不存在则由get得到None。这里的空行不是运行失败，而是实际打印了长度为零的文字。

`isinstance(value, dict)` 检查能否按本层约定把它当成字典。确认后，才读取kind。kind是分支标记，决定下一步需要什么字段。final检查text，tool检查name，陌生kind明确拒绝。不能写“不是final就按tool处理”，那会把任何拼写错误都当成工具建议。

## 三种判断不要揉成一个

字段类型、字段内容与行动许可是三件事。final的text为空，本课仍认为结构合法。tool的name若是空格，它有字符，也满足本层“非空字符串”的约定。不要自行strip后拒绝，这会增加原合同没有的规范化规则。

反过来，name为数字7不合法，即使把它显示出来也像一个名称。缺少kind、kind为未知值、value为列表都应交回False，不能为了帮忙而给输入补字段。

返回值必须是True或False。直接返回text，或者用一串 `and` 最后返回name，可能把字符串当成判断结果交出去。Python的逻辑运算会保留操作数的值，并不总会替你转换成bool；检查自己的每条返回路径。

一个从未登记过的工具名，可以在这一层返回True。结构合法只说明建议长得符合格式，不说明该工具存在，更不说明允许执行。下一课的分发器才检查登记表。把这几层分开，错误时才说得清是数据格式坏了，还是请求超出了能力范围。
