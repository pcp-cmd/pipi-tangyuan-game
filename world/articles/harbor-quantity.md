# 读懂订单数量

订单上写着 `" 12 "` 可以解释为12份，`"100"` 虽然也是整数，却超过单单上限。另一些文字连整数都不是。读懂文本与接受业务数量，是两个先后不同的判断。

本课的 `quantity(text)` 接收字符串，只在原文能由int转换且数值在0至99之间时返回这个整数，其余返回None。None表示没有接受的数量；它与合法数量0必须区分。

## 先按原文解析，再问数值是否合规

在“输入出错也不慌”中，你已经见过异常。int无法把某些文字解释成整数时会抛ValueError；try包住可能出错的转换，except ValueError处理这种失败。转换成功之后，才有整数可供范围比较。

普通Python例子只展示解析，不实现0至99的业务判断。

```python
for text in ["+١_٢", "00012", "1.5", "\x1e12"]:
    try:
        value = int(text)
        print(repr(text), value)
    except ValueError:
        print(repr(text), "不能解析")
print(int("\x1e12".strip()))
```

前两项得到12，后两项不能解析。最后一行却得到12，因为strip先删掉了原本不被int接受的控制分隔符。这个对照说明：“帮忙清理一下”可能把应拒绝的原文变成可接受输入。本课直接把原文交给int，不先strip，也不替换符号。

int本来就允许一部分首尾空白、普通正负号、Unicode十进制数字，以及合法位置的数字分隔下划线。`"1_0"`可得到10，`"1__0"`则失败；全角数字 `"１２"`可以，带全角加号的 `"＋１２"`不可以。不要用isdigit自行缩小输入集合，也不要把各种相似符号统一后再解析。

## 零不是失败，文字长度也不是范围

若用 `if value:` 决定是否有效，0会走到失败路径。应比较数值上下界，并把无结果用None表达。`"-000"`得到0，仍在范围内；`"-1"`能解析，但不在范围内。

长文本也可能是小数值。`"00012"`与 `"+00_012"`都表示12，不能用“超过两位字符”拒绝；`"000100"`才因为值为100被拒绝。先float再int会把 `"1.5"`截成1，偷偷接受了合同不允许的文本。

只处理预期的ValueError。text已经约定为字符串，这不是允许任意对象进入、遇到所有错误都吞掉的通用转换器。把两种失败都返回None，是本题明确选择，后续如果需要解释错误原因就要改变输出合同。

## 给每张订单一个可读的状态

新任务输入一列原始数量文本，每项输出 `(原文, 状态, 数值)`。状态区分 `"ok"`、`"parse-error"`、`"out-of-range"`；解析失败时数值为None，超范围时保留解析出的整数，成功时也保留整数。

这次不能把两类失败都提前压成None，否则无法告诉录入员该改文字格式还是订购数量。顺序和原文都要保留。

自核0、99、100、负数、合法前导零、非法控制符及全角符号。为每项先写预期状态，再运行对照。这份分批诊断题由你自行检查，没有接入本课自动评分。
