# 沿灯标前行

皮皮从3号灯标出发，先前进2，再后退1，最后前进4。只知道终点8，无法知道第二步是否走错。航线日志要留下起点和每一次移动后的地点。

`trace_route(start, moves)` 接收整数起点和整数步长列表，返回包含起点及每步结果的新列表。moves保留原值。正步长向前、负步长向后，零表示这一步停在原地，但日志仍要有这一笔。

## 状态是现在的位置，记录是过去的快照

你会用变量保存值，也会用列表按顺序存放多项。这里把不断变化的当前位置叫状态，把每次得到的位置存入另一个列表。先用普通Python观察潮位，手动更新两次，不写航线循环。

```python
height = 4
record = [height]
height = height - 6
record.append(height)
height = height + 1
print(height)
print(record)
```

输出-1和 `[4, -2]`。height第三次得到-1，不会让列表中已经保存的4和-2跟着改变。此处保存的是整数值，不是一个会自动追踪变量的公式。第三次更新没有append，所以记录里也不会自动多一项。

回到航线，想清楚每次循环开始时当前位置是什么，应用本次步长之后又是什么。输出里每一项应能追溯到一次明确的记录动作。没有移动时起点仍然存在，轨迹长度应当始终比moves长度多1。

## 负坐标、停留和大整数都是真实记录

从1出发走 `[-3, 1, 1, 0]`，应记录 `[1, -2, -1, 0, 0]`。遇到负位置不能自动归零，遇到相同位置不能去重，因为两笔0代表不同时间。对步长排序也会改变航线，哪怕总和不变。

不要用pop逐项取走moves里的元素，调用者之后可能还要画原路线。正常遍历就能读到每一项。也不要把moves本身当输出列表，否则会把增量与位置混在一起。

这些数是精确整数。起点9007199254740992，连续前进1再前进1，必须保留两个不同的新位置；改用浮点数可能把第一步吞掉。累计过程保留整数，不为“统一类型”先转float。

当前输入是有限列表，返回完整轨迹需要保存这些结果。它不声称支持无限流，也没有二维路径或避障规则。

## 只报告第一次越过边界

另写函数，输入起点、moves和允许区间 `[low, high]`，返回第一次离开区间的 `(移动编号, 离开后的位置)`，若一直在区间内则返回None。编号从1开始；起点已经越界则返回 `(0, start)`；边界本身允许。

这次要求找到最早事件，不再返回所有快照。离开后又回来的路线，仍然报告第一次离开，不能只检查终点。

先画一条离开后回来的路线，再测空移动、起点越界、正好到边界和零步长。自行核对最早编号及输入不变，保存路线和结果；原轨迹题通过不能替这道事件题作证。
