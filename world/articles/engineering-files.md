# 读完账本再写报告

旧报告还在桌上，新账本最后一行却可能写坏。如果程序一开始就打开旧报告准备写，旧内容会先被清空，随后才发现最后一行无法解析。正确的数量之外，这课还要保护失败时的旧结果。

入口 `summarize_file(source_path, target_path, open_file)` 得到两个路径和一个文件打开操作。open_file由本次练习提供，接口与open相同，只处理这个临时工作区。要使用它，不另开真实玩家文件。

## 文件打开以后，谁负责关闭

文件对象保存与文件系统的连接。读模式 `r` 读取，写模式 `w` 打开已有文件时会截断原内容。`with` 把打开文件的使用范围圈起来，离开范围时关闭，包括中途抛出异常。

下面在普通Python的独立临时目录演示资源关闭，内容不是数字账本。

```python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    note = Path(folder) / "note.txt"
    with open(note, "w", encoding="utf-8") as writer:
        writer.write("北岸\n南岸\n")
    print(writer.closed)
    with open(note, "r", encoding="utf-8") as reader:
        print(reader.readline().strip())
    print(reader.closed)
```

输出True、“北岸”、True。这里的TemporaryDirectory创建自己的临时目录，退出后自动回收；不要把示例改成指向自己的重要文件。课堂函数里则使用传入的open_file，并明确指定UTF-8编码。

## 先完成读取和解释，再进入写入

读取每一行后，先区分空白行与有数据的行。只含空格或制表符的行应忽略；“0”不是空白，要计为一条数值。其余行按int解析，允许负数及其合法文本形式。记录有效行数与总和。

只有全部读取和转换都成功，才开始覆盖目标报告。报告必须恰好为两行 `count=N` 与 `total=S`，每行末尾都有换行，并返回整数元组 `(N, S)`。读取为空或全是空白时，行数与总和均为0。

具体反例是源文件前两行有效，最后一行是“bad”。若边读边写目标，旧报告已经受损；若捕获ValueError后当0继续，坏数据又被伪装成有效报告。本课要求ValueError传播，旧目标原文保留，已打开的源文件关闭，源内容也不变。

这个顺序保护的是“解析失败不动旧报告”。它不自动提供磁盘写入失败、断电或多进程同时改报告的事务保证。真实原子替换需要额外设计，不要给当前课堂函数加一个没有证据的承诺。

## 报告写入时也可能失败

先说明替换前后的文件状态，再实现；原生文件替换的保证依赖同一文件系统等条件，要记录测试环境。测试坏输入、模拟写错、成功替换，并给每次保存目标的前后摘要。
