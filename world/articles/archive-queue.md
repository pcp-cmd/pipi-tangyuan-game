# 已经处理过谁，不能从等待队伍倒推

救援船按到达先后接人。名字事件把人放到队尾，感叹号事件处理最早一人。处理完成后，这个人离开等待队伍，但仍要出现在已处理记录里。只保存最后剩下的队伍，会丢掉已经完成的过程。

本课输入是有限事件列表，除精确等于 `!` 的字符串外，其余字符串都代表一次入队。相同名字可以出现多次，不应自动去重。输出是两份列表：已处理顺序与仍在等待的顺序。

## 队首与队尾各有一个动作

双端队列deque支持从两端加入或移除。下面在普通Python中观察方向，尚未写完整事件解释器。

```python
from collections import deque

waiting = deque(["A", "B"])
waiting.append("C")
served = waiting.popleft()
print(served)
print(list(waiting))
print(waiting.pop())
```

输出A、`['B', 'C']`、C。append放在右端，popleft从左端取出，构成先进先出；pop从右端取出，会把最新到达者先处理，变成另一种规则。deque的两端操作避免了列表从头删除时挪动后面所有项。

完整处理需要两个容器。等待队伍表示现在的状态，已处理列表表示完成事件的历史。处理一个感叹号前先看等待队伍是否非空，非空才移出一人并追加到历史；空队伍上的感叹号按本课规则忽略，不生成一个空姓名或None。

## 按事件顺序走一遍

事件A、B、!、C、!之后，第一次感叹号处理A，等待B；C到来后排在B后面，第二次处理B。最终历史为A、B，等待为C。若把所有感叹号数完再统一切列表，会在“先有空队列感叹号、后有人到达”时错误消耗未来的人。

用 `['!', 'a', '!', '!']` 检验空队列规则：最前与最后的感叹号都不处理人，只有中间那个完成a。用连续入队再连续出队检验方向，用两个同名事件检验是否误做去重。空事件列表应得到两份空列表。

这里是同步解释一串已经给定的事件，不涉及线程等待或异步阻塞。deque为空时popleft会抛IndexError，它不会替你等下一位人出现；要做实时救援调度，还需要新的时间和同步约定。

## 在同一等待队伍里处理取消

另设计事件为 `[动作,姓名]` 的队列系统，动作包括入队、处理和取消。取消只移除最早一位同名等待者，不改已处理记录；取消不存在的人要记入一份失败操作列表。

用同名两人、其中一人已经处理、再取消一次的事件序列核对。检查三份输出分别代表历史、现状与失败；顺序仍由事件发生顺序决定。这个任务增加了按条件移除和失败记录，不能只替换感叹号字符。自行保存逐步队列状态，不由本课自动验收。
