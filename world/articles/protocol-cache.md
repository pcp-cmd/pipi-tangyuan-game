# 报价缓存器：记住结果，也得遵守原来的调用方式

报价机器同一天对同一批货会给出相同结果。汤圆想省下重复计算，却发现一个奇怪问题：缓存热起来后，原本应当报错的调用也“成功”了。机器要求某个参数只能用关键字传入，包装函数却只看缓存键，碰巧找到旧结果就直接返回。

这课需要闭包、字典、装饰器和位置／关键字参数。闭包负责让一台报价机器记住自己的缓存；装饰器负责在真正调用前后加规则。再补一个细节：函数定义里的 `/` 左边是位置专用参数，`*` 后面是关键字专用参数。它们都是接口的一部分，缓存不能悄悄放宽。

## 先确认这次调用成立，再讨论是否省事

`inspect.signature(function)` 取得函数签名；签名的 `bind` 方法尝试把本次位置参数、关键字参数放进对应位置。它只绑定，不执行业务。缺参数、多参数、参数重复赋值或违反专用约束时，它会抛 `TypeError`。

```python
from inspect import signature

calls = []

def dispatch(parcel, /, *, urgent=False):
    calls.append(parcel)
    return urgent

shape = signature(dispatch)
bound = shape.bind("盒子", urgent=True)
print(dict(bound.arguments))
try:
    shape.bind(parcel="盒子", urgent=True)
except TypeError:
    print("绑定拒绝")
print(calls)
```

输出的参数映射是 `{'parcel': '盒子', 'urgent': True}`，随后是“绑定拒绝”和空列表。有效绑定也没有调用 `dispatch`。这给了包装层一个检查机会：先验证调用，再让计算键和业务函数产生效果。这个例子没有缓存，也没有替你补好本课装饰器。

`memoize_by_key(key_fn)` 的每次调用都要经过这一步，包括缓存已经命中的情况。随后，把原来的位置与关键字参数原样交给 `key_fn`。不要擅自把它们重排成新的调用方式；键函数也有自己的接收约定。键函数失败，业务不运行；业务失败，保留同一个错误对象，且不能把失败当成成功结果存下。

## “有这个键”与“这个结果是真的”

免费报价是 `0`，暂无报价也可能被接口定义为成功返回的 `None`。缓存命中要判断键是否存在，不能用结果的真假决定。否则免费货物会每次启动机器，返回 `False` 的检查也会不停重复。

缓存表应属于各自被装饰的函数。两个承运商都用订单号作为键，不意味着它们应共享报价；把表放在所有函数共用的位置，会让乙公司的首次查询拿到甲公司的答案。`cache_clear()` 也只清当前函数的表。

键必须可哈希。哈希相同并不代表键相等：字典还会结合相等关系区分键。用 `hash(key)` 这个整数代替原键存储，会把不同业务身份挤到同一个位置。这是一个很适合写小型反例的地方：构造两个哈希相同、内容不同的键，让它们对应不同报价。

## 包装以后，工具仍应认得原函数

`functools.wraps` 帮助保留名称、文档、注解以及 `__wrapped__` 等信息。它让读取函数的工具找到原函数，但不会自动为任意 `*args, **kwargs` 包装器执行参数校验。因此，元信息保留和调用绑定是两份责任。

还有一个容易忽略的入口：更新包装函数元信息时，原函数的自定义属性可能也会被带过来。如果原函数恰好有名为 `cache_clear` 的属性，你不能让它覆盖自己的清理方法；缓存内部状态同样需要保护。检查时同时观察返回值、真正调用次数、清理效果和 `inspect.signature`，只看其中一个不够。

本课只处理普通同步函数，没有规定线程安全、容量淘汰、过期时间或异步任务共享。缓存也不自动深复制结果；调用者修改一个缓存中的列表，后续查询可能看到同一对象的变化。发送通知、扣款这类外部操作不能因为“同参数”就直接套这份缓存合同。

## 独立任务：报价发生了版本更新

设计一个多租户商品查询缓存。同名商品在不同租户下可能不同，价格表每次更新都有整数版本号；相同租户、商品、版本可复用结果，版本变化必须重新查询。查询可能暂时失败，失败后允许重试。先说明完整键应表达哪些业务事实，再决定如何让一个租户的旧版本失效，同时不清掉另一租户的数据。

提交自己的调用轨迹和断言：至少覆盖跨租户同名商品、版本切换、成功值为 `0`、首次失败后成功，以及非法参数在缓存预热后仍被拒绝。还要解释缓存中可变结果由谁拥有。这里增加了版本与局部失效策略，不能只换个函数名照抄；它需要人工审查你的键设计与失效证据，当前课程检查不替它判定。
