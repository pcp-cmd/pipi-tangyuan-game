# 一次授权的一次航行

汤圆批准皮皮买一份鱼饼，过了一会儿请求变成买十份。动作名字仍叫buy，操作者也没变，但那张批准单已经不能说明新的数量被允许。授权要绑定具体请求，不能只看一个“已批准”标志。

本课实现 `authorized(grant, actor, action, args, now)`。grant必须包含actor、action、args、expires和used。主体、动作、参数都要与当前请求精确匹配，used必须是布尔False，当前时间严格早于expires。返回bool，不修改grant。

## 当前请求与当时批准的内容逐项比对

前一课检查输入是否像一份合法请求，这一课检查请求是否仍是批准的那一份。相同主体不能代替相同动作，相同动作不能代替相同数量。缺字段时应拒绝，而不是为缺失的时间或参数猜一个默认值。

args是普通JSON字典。比较要忽略对象键写入的先后，同时区分布尔值与数值。Python的普通相等规则与这里的JSON内容要求有差别。

```python
import json
left = {"open": True}
right = {"open": 1}
print(left == right)
print(json.dumps(left, sort_keys=True))
print(json.dumps(right, sort_keys=True))
```

输出先为True，随后是 `{"open": true}` 与 `{"open": 1}`。JSON保留了布尔与数值的区别。对本课限定的普通JSON内容，可以依据稳定的字段次序比较表示；这不是任意Python对象的比较器，也不是防篡改签名方案。

同样内容按另一种键顺序建立的字典仍应匹配。不能用未经整理的字典字符串表示，把键顺序当成请求变化。列表中的顺序则属于内容，不能为追求“稳定”把所有容器都排序。

## 到期边界与使用状态

expires为20，now为19时尚在有效期，now恰好为20已经过期。这个边界要用严格小于，不能多给一个时刻。时间在本课以整数表示，不涉及现实时间同步或时区。

used也有精确要求。False表示未使用，数字0、空字符串或None不能代替它。若只写 `not grant["used"]`，这些值都会被当成未使用，偏离合同。

本函数只检查，不消费。两次用相同输入调用，不能因为第一次检查成功就把used改成True。要让“检查并消费一次”在并发环境下可靠，需要把它们放进一次不可分开的状态修改；纯函数的一次True不提供这项保证。

可靠派送工程会把草稿版本、期限复查、批准消费和任务登记放进真实SQLite流程。本课没有签名、真实身份核验或数据库事务，不能把当前通过解释为完成了生产授权系统。

## 把批准绑定到文件版本

新任务批准修改一份文档。批准中保存文档ID、内容摘要、允许的操作和到期时间。执行前重新读取当前内容，只有摘要仍相同才能继续；文件名相同但字节已变，应拒绝旧批准。

先用两段普通文字模拟两个版本。分别检查同名改字、换ID、到期时刻、重复使用和完全匹配。说明为什么不能用“字数一样”代替内容摘要，也不能把检查看成真正写入。

这道题由你在原生Python中人工核对，可先让允许操作只追加一条内存事件。真实文件修改与恢复可在可靠修补工程继续实践；本迁移不会自动授予工程成绩。
