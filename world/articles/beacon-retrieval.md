# 先看权限再找证据

档案馆里有公开海图，也有只给汤圆看的维修笔记。皮皮搜索“海图”时，相关程度再高的私有笔记也不能进入他的候选资料。先找最相关的几份再删私有文档，可能让不该参与的内容影响结果，还会错过真正可读的资料。

本课的 `retrieve(docs, actor, query)` 先限制到actor有权读取的文档，再匹配区分大小写的query子串。每份文档包含id、text和allowed列表，返回命中文档的id，按id排序。query为空时返回空列表。

## 权限先决定搜索范围

`actor in doc["allowed"]` 回答这个主体是否在可读名单里。它不检查文章讲什么，也不表示工具已经读取了真实文件。本题收到的是内存文档字典，练习的是处理顺序。

先用一张独立门禁名单观察成员关系。

```python
allowed = ["pipi", "tangyuan"]
print("pipi" in allowed)
print("guest" in allowed)
ids = ["c", "a", "b"]
print(sorted(ids))
print(ids)
```

输出为True、False、`['a', 'b', 'c']`和`['c', 'a', 'b']`。sorted返回新列表，原顺序没有改变。这个小例分别展示名单检查与输出排序，完整检索还要把权限和文本匹配按合同组织起来。

## 这次不要照搬上一门检索课

前面的航海笔记检索忽略英文大小写，并让空查询匹配全部。本课刻意采用另一份合同。`"Sea"`不能匹配`"sea"`，空查询返回 `[]`，结果是id而不是原文，也不要求沿用输入顺序。

这些区别来自用途。当前入口提供有权限的文档定位符，不应让空查询意外列出全部资料。相同函数名不意味着可以直接搬来旧实现；先写清输入、匹配规则和返回内容。

query可以出现在text中间或结尾，不只是开头。不要把子串判断误写成startswith。排序只在收集完可读命中后做，不能把没有权限的id也放进结果再让显示层隐藏。

本题默认文档满足给定字段结构，不要求在这里发明缺字段修复逻辑。实际系统中的身份可信度、文件访问、来源更新和引用真实性需要另行处理。命中某个词也不表示文档支持最终结论。

## 怎样证明没有借私有资料得出结论

构造两份文字完全相同、allowed不同的文档。换actor后，结果应随权限变化。再把私有文档的内容改得更像查询，仍不应影响当前actor结果。最后用相反大小写与空query检查你没有偷偷继承旧规则。

“档案馆·可复查的研究”工程会在真实文件与索引上进一步检验权限前置、资料撤回和发布前版本核对。当前课堂只是其中一段内存逻辑，下载工程或作者检查通过不能代替学习者自己的研究证据。

## 同一条结果，给出可读的证据片段

新任务仍先过滤权限，但返回每份命中文档中第一个query出现的位置与一段固定长度的附近文字。不得从私有文档生成摘要，片段边界不能越过文本开头或末尾，空query仍无结果。

先规定片段最多保留命中前后多少字符，再测试命中开头、结尾、重复出现和中文文本。说明返回位置针对原文还是截取后的片段，并保持这个定义一致。

这道迁移新增定位与片段边界，按自己的合同人工核对。原课的id列表通过不自动证明片段处理正确，也不能作为可信引用审核。
